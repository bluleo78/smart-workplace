# 매뉴얼 집필

`docs/manual/` 아래 장을 쓰거나 고칠 때 쓴다. 저장소 독자용 안내(명령·폴더)는 `docs/manual/README.md` 에 있고, 이 문서는 **집필자용 규칙**이다.

## 핵심 원칙

**화면에 없는 기능·문구·AI 결과를 지어내지 않는다.** 이 앱은 i18n 파일이 없어 화면 문구가 컴포넌트에 직접 들어 있다. 버튼·필드·탭 이름은 `apps/workplace-web/src`(운영자 매뉴얼은 `apps/workplace-admin/src`)에서 정확한 한국어 문자열을 grep 으로 찾아 옮긴다. 기억이나 추측으로 쓴 문구는 화면과 어긋나고, 어긋난 매뉴얼은 소개서의 근거가 될 수 없다.

## 근거의 우선순위

장을 쓰기 전에 이 순서로 읽는다. 위쪽이 더 강한 근거다.

| 알아야 할 것 | 근거 |
| --- | --- |
| 화면 목록·경로 | 라우터 `apps/workplace-web/src/App.tsx`(운영자: `apps/workplace-admin/src/App.tsx`). 리다이렉트·`ComingSoon` 은 화면이 아니다 |
| 메뉴 이름·순서 | 레일 `components/layout/AppRail.tsx`, 설정 내비 `components/layout/SettingsSidebar.tsx`, 작업 관리 사이드바 `components/issue/IssueSidebar.tsx` |
| **버튼·필드·탭 문구** | 해당 화면 컴포넌트의 한국어 문자열(JSX 텍스트·`label`·`placeholder`·`aria-label`) |
| 조작 순서·결과 | 해당 화면의 `*.test.tsx`, `apps/workplace-web/e2e` |
| AI 가 하는 일·권한 | `apps/workplace-ai-agent/src/agent` 의 시스템 프롬프트(`system-prompt.ts`·`assistant-system-prompt.ts`)와 서브에이전트 `subagents/*/agent.md`, 도구 정의 `src/mcp/tools.ts` |
| 외부 AI 도구 연동(MCP) | `apps/workplace-mcp/src/tools/index.ts` |

화면이 실제로 있는지는 라우터로 판단한다. 문서·이슈의 완료 표기보다 라우터가 우선이다.

## 작성 순서

1. 위 표대로 근거를 읽는다.
2. **촬영 대상 표에 그림 행을 먼저 넣는다**(`docs/manual/shots/targets.md`). 그다음 장면(`scripts/scenes/<book>.mjs`)을 쓰고 찍는다.
3. 초안을 쓴다. 화면 문구는 소스에서 옮겨 **굵게** 쓴다.
4. 실제 화면으로 검증한다 — 코드만 읽고 쓴 절차는 틀린다(smart-dcim 매뉴얼은 라이브 검증에서 진입 위치·화면 범위 어긋남을 다수 찾았다).
5. 코드로 답이 안 나오는 정책은 `> TODO(정책): …` 로 남긴다. 추측해서 채우지 않는다. 장마다 끊어 묻지 않고, 전 장 초안이 끝난 뒤 모아서 한 번에 사용자에게 묻는다.
6. 아래 「장 마무리 점검」을 통과시킨다.

`> TODO(집필): …` 은 아직 못 쓴 자리 표시다. `pnpm manual:prose` 가 오류로 잡으므로 장을 끝내기 전에 모두 없앤다. `TODO(정책)` 은 검사를 통과한다(PDF 에 회색 상자로 보인다).

## 프론트매터

```markdown
---
slug: ai-collaboration
title: AI 와 함께 일하기
part: 1
audience: [member, admin]
routes: [/me/ai-tasks]
---
```

| 필드 | 규칙 |
| --- | --- |
| `slug` | 파일명 `NN-<slug>.md` 에서 번호를 뺀 값. **바꾸지 않는다** — 그림 id·장 앵커(`#ch-<slug>`)가 된다 |
| `title` | 장 제목. 한글 명사구. 레일에 있는 앱은 레일 표기를 그대로 쓴다(레일이 「대화」면 장 제목도 「대화」) |
| `part` | 사용자 매뉴얼의 부 번호: 1 시작하기 · 2 앱 · 3 개인 설정 · 4 관리자 설정 · 5 참조. 운영자 매뉴얼은 부가 없어 생략 |
| `audience` | `member`(구성원) · `admin`(관리자) · `operator`(슈퍼어드민). 장 머리 배지가 된다 |
| `routes` | 이 장이 덮는 라우터 경로. **한 줄 대괄호**로 쓴다(여러 줄 YAML 은 검사가 거부). 화면이 없는 장은 `[]`. 한 경로는 한 장만 덮는다 |

파일명은 ASCII 만 쓴다. 번호는 순서가 바뀌면 바꿔도 되지만 `slug` 는 고정이다.

## 그림 지시문과 boxes.json

한 줄 전체가 그림 지시문이다.

```markdown
![담당자 목록 — 사람과 AI 가 한 목록에 함께 보입니다](shots/user/ai-collaboration-2.png){crop=picker marks=picker,agent}
```

- `shots/<book>/<id>.png` 는 촬영 원본(2880x1620, 뷰포트 1440x810 배율 2, 라이트 테마)이다. 다크 모드 그림은 싣지 않는다 — 테마를 바꾸는 장면도 바꾸기 전(라이트) 화면만 찍고, 촬영 컨텍스트가 문서마다 테마를 라이트로 되돌린다. 원본과 `boxes.json` 은 커밋한다. 운영자 매뉴얼만 뷰포트 900x810(원본 1800x1620)으로 찍는다(`scripts/lib/books.mjs` 의 `capture.viewport`) — 콘솔 본문이 화면 폭을 다 써서 1440 폭에서는 제목과 오른쪽 단추가 원본 2400px 가까이 벌어져 자르기 기준을 지킬 수 없기 때문이다. 인쇄 배율은 원본 px 기준(`FULL_WIDTH_PX`)이라 두 권이 같다.
- `boxes.json` 은 `{ "<id>": { "w": 2880, "h": 1620, "boxes": { "<키>": { "x", "y", "w", "h" } } } }` — 원본 px 좌표. 촬영 스크립트가 Playwright `boundingBox()` 로 기록한다(`rec.mark`). **손으로 좌표를 지어 넣지 않는다.**
- `crop=a+b` 는 상자 a·b 의 합집합 + 여백 48px(`CROP_PAD_PX`)로 자른다. 생략하면 전체 화면.
- `marks=a,b` 는 적은 순서대로 1·2 번호 표식과 빨간 테두리를 얹는다. 표식은 그림에 굽지 않고 빌드 때 얹는다(화면이 바뀌면 다시 찍기만 하면 된다).
- 번호 원은 상자 **바깥**에 그려 상자 안 글자를 가리지 않는다. 빌더(`figure.mjs` 의 `placeMarks`)가 왼쪽 위 → 왼쪽 가운데 → 오른쪽 위 → 오른쪽 가운데 → 왼쪽 아래 → 오른쪽 아래 순서로, 자른 프레임 안에 들어가고 다른 표식 상자·번호와 겹치지 않는 첫 자리를 고른다(세로로 촘촘한 레일 아이콘은 옆 가운데가 뽑힌다). 넓게 자르면 번호 자리가 커지므로 자르기 여백도 그만큼 늘어난다.
- 바깥 어디에도 자리가 없으면 조용히 안쪽에 넣지 않고 `manual:check`·빌드가 실패한다 — 이웃 상자를 `crop` 에 더해 넓힌다. 자동으로 고른 자리가 표식 없는 화면 요소(머리말 아이콘, 이웃 단추)를 덮으면 `marks=key@r` 처럼 자리를 직접 고른다(`tl`·`l`·`tr`·`r`·`bl`·`br`, 같은 검사를 받는다). 상자 안이 꼭 필요하면 `key!inside`(상자 안 오른쪽 위 — 앞쪽 아이콘·글자를 피하는 자리)를 쓴다. 둘 다 PDF 를 그림으로 그려 눈으로 확인한 뒤에만 쓴다.
- 그림 바로 뒤의 번호 목록은 번호가 표식과 같은 빨간 원으로 그려진다(시안 B). 그래서 그림과 절차 사이에 다른 문단을 끼우지 않는다 — 끼우면 평범한 번호 목록이 된다.
- 표식 상자는 자르기 영역 안에 있어야 한다. 밖이면 빌드가 멈춘다. 모르는 키·없는 그림·알 수 없는 속성(`corp=` 같은 오타)도 검사·빌드 실패다.
- alt 는 그림 설명(figcaption)으로 찍힌다. 「무엇을 보여 주는 그림인지」를 한 줄로 쓴다.
- AI 결과 영역의 표식은 문구가 아니라 **영역 컨테이너**(카드·패널)에 건다. AI 문구는 다시 찍을 때마다 달라진다.

### 자르기 가독성 기준

**태스크 그림 자르기 폭은 원본 1400px 이하**로 한다.

- 근거: 본문 폭(A4 세로, 여백 18mm → 약 174mm = 96dpi 에서 657px)에 그림이 꽉 차게 들어가므로, 원본 폭 W 의 화면 글자(14 CSS px = 원본 28px)는 인쇄에서 `28 x 657 / W` px 가 된다. 2026-10-29 샘플(04장)을 PDF 로 빌드해 96dpi 로 그려 보고 같은 그림을 폭만 바꿔 비교했다.
  - 1200px: 화면 글자가 본문(10.5pt)과 비슷하다.
  - 1400px: 본문보다 조금 작지만 편히 읽힌다 — **기준**.
  - 1600~1700px: 읽히지만 작다. AI 결과 카드처럼 글을 읽힐 필요가 없는 그림만 이 폭까지 허용한다.
  - 2000px 이상: 눈을 찡그려야 읽히고, 2400px 이상은 사실상 안 읽힌다.
- **전체 화면 그림은 「어디인지」 보여 줄 때만** 쓴다(장 첫 그림, 화면 구조 설명). 전체 화면 그림의 글자는 읽히지 않는다고 보고, 읽혀야 하는 문구는 본문에 굵게 적는다.
- 자르기를 좁히려면 표식 상자도 좁아야 한다(표식은 자르기 안에 있어야 한다). 표식 상자가 넓은 컨테이너면 촬영 때 더 좁은 요소의 키를 따로 기록한다.
- **모든 그림은 같은 배율로 인쇄된다.** 빌더(`scripts/lib/figure.mjs` 의 `FULL_WIDTH_PX = 1400`)가 원본 1400px 을 본문 단 폭으로 보고, 자른 폭에 비례해 그림 폭을 정한다(640px 이면 단 폭의 약 46%, 가운데 정렬). 1400px 보다 넓은 그림은 단 폭에서 멈추므로 글자가 그만큼 작아진다. 기준을 바꾸면 이 상수도 같이 바꾼다.
- 얇은 띠(높이가 원본 200px 안팎)로 자르면 어느 화면인지 알 수 없다. 탭·제목 같은 주변 요소의 키를 함께 기록해 `crop=a+b` 로 맥락을 넣는다.
- 모바일 화면(390x844 배율 3)은 쪽 폭의 절반 정도로 두 장 나란히 둔다.

## 도움말 표시와 자리표시

사용자 매뉴얼은 앱 도움말 패널·MCP·검색 색인의 원본이다. 빌드가 장을 **절 단위**로 잘라 도움말 묶음을 만들고(`pnpm manual:help`), 화면은 그 절 하나를 패널에 띄운다. 그래서 아래 표기를 쓰고, `pnpm manual:check` 가 두 권 모두 검사한다. 근거: `docs/superpowers/specs/help-panel-design.md` 9절·14절.

### 도움말 id 가 붙은 절은 그 절만 읽어도 통하게 쓴다

도움말 패널은 그 절 하나만 보인다 — 앞 절도, 하위 절도 보이지 않는다(절 본문 = 제목 다음 줄부터 다음 제목 앞까지).

- 「위에서 말한」·「앞 절의」·「이 화면에서」처럼 앞 글에 기대는 말을 쓰지 않는다. 필요한 맥락(어느 화면인지, 무엇을 먼저 했어야 하는지)은 한 문장으로 다시 적거나 절 링크로 보낸다.
- 하위 절에 넣은 절차는 상위 절 도움말에 보이지 않는다. 상위 절에는 한두 문장 요약과 하위 절 링크를 둔다.

### 표기

절 제목 **끝**에 단다.

```markdown
## 저장소 토큰을 연결한다 {help=agent.run.repo label=저장소 연결}
```

- id: 소문자·숫자·하이픈 마디를 점으로 잇는다(`agent.run.repo`). 대문자·`_`·빈 마디(`a..b`)는 안 된다. **책 전체에서 하나**다.
- 점은 층이다. `agent.run.repo` 는 `agent.run` 절 **아래 층 제목**에 둔다. 층이 어긋나면(형제 절에 하위 id, 남의 절 아래에 다른 id) 브레드크럼과 id 올라가기가 서로 다른 길을 보여 검사가 실패한다(`[도움말 층 어긋남]`).
- `label=` 은 화면 칸 이름을 그대로 쓴다(브레드크럼·패널 머리에 보인다). 생략하면 제목이 쓰인다. 빈 `label=` 은 오류.
- 장 제목 줄(`# `)에 달면 장 첫머리(첫 `##` 앞 글)의 id 가 된다.
- 제목 끝 밖(본문 줄·목록·제목 가운데)의 `{help=…}`, 속성 오타(`lable=`)는 검사 오류다. PDF 는 제목 끝의 올바른 표시만 지운다.
- 제목을 `_` 로 시작하지 않는다(장 첫머리 절 `#_intro` 몫, `[예약 slug]`).

### 절 링크

`[글](NN-slug.md#<id 또는 제목 slug>)`, 같은 장이면 `[글](#…)`. 도움말 패널의 「관련」 목록과 절 이동이 이 링크에서 나온다. 앵커는 먼저 도움말 id(다른 장 파일을 적었으면 그 장의 id 여야 함), 아니면 GitHub 방식 제목 slug(같은 제목이 또 있으면 `-1`, `-2`)로 찾는다. 못 찾으면 `[절 링크 없음]`. 장 파일만 적으면 그 장 첫머리로 간다.

### 자리표시

화면이 실제 값으로 채운다. 목록 밖 이름은 오류(`[자리표시 없음]`) — 새 자리표시는 화면이 그 값을 넘겨주는지 확인하고 `docs/manual/scripts/lib/help-vars.mjs` 에 더한다.

| 이름 | 뜻 | PDF 표시 |
| --- | --- | --- |
| `{agent.username}` | 그 AI 의 아이디(에이전트 상세) | <AI 아이디> |
| `{app.mcpEndpoint}` | 이 서버의 MCP 주소 | <MCP 주소> |
| `{app.origin}` | 이 앱의 주소(플러그인 마켓플레이스 주소 등) | <앱 주소> |

- 산문·인라인 코드·코드 블록 안 모두 쓸 수 있다. 코드 블록은 도움말에서 복사 단추가 붙으므로, 사용자가 붙여 넣을 명령에 자리표시를 넣으면 값이 채워진 채 복사된다.
- **제목과 그림 지시문 줄에는 쓰지 않는다**(`[자리표시 위치]` — 브레드크럼·그림 설명에 날것이 보인다).
- 코드 안에서는 **목록에 있는 이름만** 자리표시로 보고 JSON(`{"a":1}`)·셸 `${HOME}`·JS 템플릿 `${x.y}`·JSX `{props.title}` 같은 목록 밖 글자는 오류 없이 그대로 둔다(산문에서는 목록 밖 `{이름.이름}` 이면 `[자리표시 없음]`). 산문에서 중괄호 글자를 그대로 보이려면 `\{` 로 쓴다(산문의 알 수 없는 `{…}` 는 `[알 수 없는 표기]`).

### 조건 블록

특정 서버에서만 맞는 절차를 감싼다. 화면은 조건이 맞을 때만 보이고, PDF 는 꼬리표와 함께 늘 보인다.

| 조건 | 언제 보이나 | PDF 꼬리표 |
| --- | --- | --- |
| `app.customMcpServer` | 이 서버의 MCP 주소가 기본 주소가 아닐 때 | (기본 주소가 아닌 서버만) |

두 꼴만 쓴다.

```markdown
한 줄 안: … {if app.customMcpServer}이 글만 조건부{/if} …

줄 단위(여는 줄·닫는 줄이 그 표기만, 들여쓰기 허용 — 목록 항목을 감쌀 수 있다):
{if app.customMcpServer}
- 기본 주소가 아니면 주소를 직접 넣는다
{/if}
```

- 중첩, 코드 블록 안의 `{if …}`, 다음 제목을 넘는 블록, 짝 없는 `{/if}`, 목록에 없는 조건 이름은 검사 오류(`[조건 블록]`). 닫히지 않은 블록은 PDF 빌드도 멈춘다.
- 인라인 코드 안의 `` `{if …}` `` 는 오류가 아니라 글자 그대로 보인다(표기 설명을 적을 때 이렇게 쓴다).
- HTML 주석 `<!-- … -->` 안의 중괄호(조건·자리표시·`{foo}`)는 표기로 보지 않는다 — 검사·도움말 묶음·PDF 가 모두 건너뛴다. 닫는 `-->` 가 없으면(줄 가운데서 연 주석은 같은 문단 안에 없으면) 주석이 아니라 그대로 검사한다.

### 도움말 그림

그림 지시문마다 PDF 와 같은 자르기·번호 표식을 얹은 PNG 를 미리 만들어 `docs/manual/help-figures/user/` 에 커밋한다(웹 빌드에는 브라우저가 없어 빌드 때 그릴 수 없다). **다시 찍었거나(`manual:shots`) 그림 지시문의 crop·marks 를 바꾸면 `pnpm manual:help-figures` 를 돌려 바뀐 PNG 와 `manifest.json` 을 함께 커밋한다.** 잊으면 `manual:check` 가 `[도움말 그림 없음]`·`[도움말 그림 오래됨]` 으로 실패한다. 그림 바로 뒤 번호 목록의 n번째 항목 첫 문장이 n번 표식의 설명이 되므로, 표식과 절차 번호를 맞추는 규칙(위 「그림 지시문과 boxes.json」)이 도움말에서도 그대로 쓰인다.

### 화면의 `data-help`

화면 요소의 `data-help="<id>"` 는 매뉴얼에 그 id 를 가진 절이 있어야 한다(`[data-help 짝 없음]`, 형식이 틀리면 `[data-help 형식]`). 값을 변수로 넘긴 곳은 검사가 셀 수만 있다(`[data-help 동적]` 정보 줄). 화면에 도움말을 붙이면 같은 작업에서 매뉴얼 절에 id 를 단다.

## 촬영 환경

| 권 | 촬영 환경 |
| --- | --- |
| 사용자 매뉴얼 | **운영 환경의 매뉴얼 전용 가상 테넌트**(운영 검증용 테넌트와 섞지 않는다). 계정은 `example.com` 가상 인물만 |
| 운영자 매뉴얼 | **격리 로컬 스택**(개발용 포트와 겹치지 않는 포트, 매번 깨끗한 DB). 운영 슈퍼어드민 화면에는 실제 고객사 이름이 보이므로 운영에서 찍지 않는다 |

- **운영에 쓰는 일(시드 실행, 테넌트 초기화)은 매번 사용자 확인 뒤에** 한다. 데이터는 API 로만 넣는다(DB 직접 쓰기 금지).
- 실명·실계정·운영 데이터가 그림에 찍히면 안 된다.
- 결정적으로 찍는다: 토스트 숨김·애니메이션 0초(촬영 컨텍스트 스타일)와 입력 커서 숨김(`rec.shoot`)은 촬영 도구가 한다. 상대 시각·자동 순회는 장면이 끄거나 고정한다. `networkidle` 대신 실제 요소 등장을 기다린다.
- 배포되지 않은 기능은 찍을 수 없다. 매뉴얼 갱신은 릴리스 뒤에 한다.
- 부분 재촬영: `MANUAL_SHOTS_ONLY=id,... pnpm manual:shots`. 화면이 바뀐 장만 다시 찍는다.

## 제목 어법

- **장 제목은 명사구** — 「AI 와 함께 일하기」, 「캘린더」. 장 제목은 프론트매터 `title` 이다(본문 첫 `# ` 줄은 빌드가 버린다).
- **절 제목(`##`)은 태스크 문장** — 「AI 에게 일을 맡긴다」, 「맡긴 일을 한곳에서 본다」. 독자가 실제로 찾는 형태다.
- 한 절에 그림이 둘이면 그림마다 `###` 소절로 나눈다(번호 목록이 그림마다 1부터 다시 시작한다).

## 문체

「…누릅니다 / 입력합니다」 형태(합니다체 서술)로 쓴다. 사용자용이므로 하십시오체 명령형보다 부드럽게 한다.

| 규칙 | 나쁨 | 좋음 |
| --- | --- | --- |
| 절차는 「…합니다」 | 담당자를 선택하십시오 | **담당자** 칸을 누릅니다 |
| 한 단계 한 동작 | 이름을 입력하고 유형을 고른 뒤 저장합니다 | (세 단계로 나눈다) |
| 1인칭 배제 | 우리는 이 설정을 권장합니다 | 이 설정을 권장합니다 |
| 화면 요소는 굵게 | 저장 버튼을 누릅니다 | **저장** 을 누릅니다 |

- 번호 절차는 **7단계 이내**. 넘으면 절을 나눈다.
- **표식 번호 = 절차 번호.** 그림의 n 번 표식은 절차 n 단계의 대상이다. 표식이 없는 단계는 표식 있는 단계 뒤에만 둔다.
- 굵게 문구는 닫는 `**` 뒤에 띄어쓰기를 둔다(`**AI 에게 요청…** 칸에`). 닫는 `**` 앞이 구두점이고 바로 뒤가 글자면 별표가 그대로 찍힌다 — `manual:prose` 가 오류로 잡는다.
- 화면 문구가 아닌 것(AI 배지의 「AI」 같은 영문 표시, 일반 명사)은 굵게 쓰지 않고 「」로 감싼다.
- 장 참조는 0 을 붙이지 않는다 — 「8장」. 링크는 `[8장](08-work.md)` 형태로, **책에 있는 장에만** 건다(없는 장을 가리키면 빌드가 멈춘다).
- 본문에 저장소 경로 링크를 두지 않는다. PDF 에서 죽는다. 처음 쓰는 사람에게 필요한 절차는 본문에 담는다.

## 「AI 와 함께」 절

앱 장(5~11장)마다 같은 이름·같은 모양의 절을 둔다. 제목이 `AI 와 함께` 로 시작하는 `##` 절은 빌드가 보라 띠 상자로 감싼다.

```markdown
## AI 와 함께 — 메일을 요약하고 답장 초안을 받는다
```

- 제목은 `AI 와 함께 — <태스크 문장>` 형태로 쓴다.
- **AI 결과 문구를 인용하지 않는다.** 「무엇이 나오는지」만 설명한다(요약이 나온다, 체크리스트가 코멘트로 남는다). 다시 찍으면 문구가 달라진다.
- **AI 의 권한을 뭉뚱그리지 않는다.** 기능마다 셋 중 무엇인지 구분해 쓰고, 각각 근거를 확인한다.

| 구분 | 뜻 | 근거 예(04장) |
| --- | --- | --- |
| 직접 실행 | AI 가 사람 승인 없이 바꾼다 | 이슈 담당자로 맡긴 AI 는 코멘트·상태·담당자 변경, 하위 이슈 생성을 직접 한다(`system-prompt.ts`) |
| 제안 후 승인 | 확인 카드가 뜨고 사람이 **승인** 해야 실행된다 | AI 어시스턴트의 삭제처럼 되돌리기 어려운 작업은 `propose_*` 도구가 확인 카드를 만든다(`assistant-system-prompt.ts`, `subagents/issue-agent/agent.md`, 카드 단추는 `AIChatPanel.tsx`) |
| 읽기만 | 조회·정리만 하고 쓰지 않는다 | 개인 작업의 반복 실행은 쓰기 도구가 없고 결과에 제안만 남긴다(`RECURRING_RUN_SYSTEM_PROMPT`) |

근거를 못 찾으면 `> TODO(정책): …` 로 남긴다. 「AI 의 변경은 사람이 승인한다」 같은 뭉뚱그린 문장은 쓰지 않는다 — 담당자로 맡긴 AI 는 승인 없이 바꾸므로 틀린 문장이 된다.

세 단계만 쓴다. 라벨 줄 다음에는 반드시 빈 `>` 줄을 둔다(없으면 다음 줄이 라벨에 붙는다 — 검사가 잡는다).

## 이모지 금지

**매뉴얼에 이모지를 쓰지 않는다.** 알림 상자·목록·표 모두 예외 없다. PDF 렌더가 깨지고, 화면 낭독기가 이름을 그대로 읽는다. ✦ ★ ✓ 같은 기호도 이모지 검사에 걸린다(허용: `→ ← ↑ ↓ ▸ · —`). 강조는 **굵게** 와 알림 상자 라벨로 한다.

## 화면을 바꾸면 매뉴얼도 고친다

화면(경로·메뉴·버튼 문구·조작 순서)을 바꾸는 작업은 **같은 작업에서 해당 매뉴얼 장도 고친다.** 그림이 달라졌으면 촬영 대상 표의 행을 확인하고 그 그림만 다시 찍은 뒤 `pnpm manual:help-figures` 로 도움말 그림도 다시 만든다. smart-dcim 매뉴얼은 마감 열흘 만에 화면이 바뀌어 9개 장과 그림 전부를 다시 고쳤다. `manual:check` 는 최소한 경로 추가·삭제를 잡는다.

## 하지 않는 것

- 미구현 기능을 쓰지 않는다. 라우터에 없거나 `ComingSoon` 이면 화면이 없는 것이다.
- 설치·배포·릴리스 절차를 옮겨 적지 않는다. 매뉴얼은 **화면에서 무엇을 하는가**만 다룬다.
- AI 결과 문구를 인용하지 않는다. 결과 문구를 손으로 넣어 찍지 않는다(AI 결과물은 실제 AI 호출로 만든다).
- 운영 데이터·실명·실계정을 본문과 그림에 넣지 않는다.

## 장 마무리 점검

장을 끝내기 전에 확인한다.

- [ ] `pnpm manual:check <book>` 에 그 장 관련 오류가 없다 — 프론트매터, 경로 대조(유령·중복), 이모지, 그림·표식 키, 도움말 표시·절 링크·자리표시·조건 블록

- [ ] `pnpm manual:prose <book>` 이 통과한다 — 알림 상자 표기, 장 번호 앞 0, 강조 미종결, 남은 `TODO(집필)`
