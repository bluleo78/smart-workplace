# genia-works — Claude Code 플러그인

Claude Code 에 genia-works MCP 서버를 연결하고, **세션마다 접속 신원**(내 토큰 또는 AI 사용자 키)을 고르게 해 주는 플러그인입니다. 이슈를 맡아 일하면서 진행 상황을 이슈에 보고하는 스킬과, AI 에게 할당된 이슈를 자동으로 하나씩 처리하는 스킬도 함께 들어 있습니다.

- 설치 한 번으로 연결됩니다. `claude mcp add …` 명령을 복사해 붙일 필요가 없습니다.
- 같은 컴퓨터에서 세션마다 신원을 따로 고릅니다. 한 세션에서 바꿔도 다른 세션은 영향을 받지 않습니다.
- 토큰과 키는 대화창에 붙이지 않습니다. 대화 기록과 모델 입력에 남지 않게 하려는 것입니다.

## 설치

Claude Code 안에서 두 줄을 실행합니다. 목록 주소는 접속하는 웹 주소 기준입니다(운영: `https://genia-works.iacloud.kr`).

```
/plugin marketplace add https://genia-works.iacloud.kr/claude/marketplace.json
/plugin install genia-works@genia-works
```

- 설치할 때 **내 API 토큰**(설정 › API 토큰에서 발급한 `swp_…`)을 물으면 붙여 넣습니다.
- 묻지 않았거나 나중에 바꾸려면 `/plugin configure genia-works@genia-works` 를 실행합니다(또는 `/plugin` › genia-works › 설정).
- 토큰은 민감 항목이라 Claude Code 가 운영체제 보안 저장소에 둡니다. 설정 파일에 평문으로 남지 않습니다.
- `claude plugin install … --config token=…` 처럼 명령줄에 토큰을 적지 마세요. 셸 기록에 남습니다.
- `/mcp` 에서 `plugin:genia-works:genia-works` 가 연결됐는지 확인합니다.

### 설정 항목

| 항목 | 기본값 | 설명 |
|---|---|---|
| 서버 주소 (`server_url`) | `https://genia-works.iacloud.kr/mcp` | 로컬 개발이나 다른 배포에서만 바꿉니다(기본 주소가 아닌 서버의 웹 화면은 이 설정을 바꾸라고 안내합니다). 범위를 좁힌 주소(예: `/mcp/readonly`)도 쓸 수 있습니다 |
| 내 API 토큰 (`token`) | 없음 | 기본 신원입니다. 민감 항목입니다 |

### 바뀌는 점

- **도구 이름**: 플러그인이 연결한 도구는 `mcp__plugin_genia-works_genia-works__<도구>` 로 보입니다(예: `mcp__plugin_genia-works_genia-works__list_issues`). 허용 목록(`permissions.allow`)이나 스킬·명령에 `mcp__genia-works__…` 가 적혀 있으면 새 이름으로 고치세요.
- **예전 수동 등록 자동 정리**: 예전에 `claude mcp add` 로 같은 주소를 `genia-works` 로 등록해 두었으면, 그 등록이 플러그인 연결을 가립니다. 세션이 시작될 때 플러그인이 이를 찾아 정리합니다.
  - 헤더에 AI 키(`Bearer ak_…`)를 담은 등록은 **지우지 않습니다**. 지우면 그 프로젝트의 신원이 내 계정으로 바뀌고 키도 잃기 때문입니다. 「AI 키로 연결돼 있어 그대로 둡니다」라고 알리니, 그 키를 `/genia-works:login` 으로 등록한 뒤 안내된 `claude mcp remove` 로 직접 지우세요.
  - 비대화형(`claude -p`·SDK) 세션에서는 알림이 보이지 않으므로 정리하지 않습니다.
  - 대상은 **주소가 정확히 같은 등록**뿐입니다. 출처(scheme·호스트·포트)와 경로가 같아야 하고, 끝의 `/` 하나만 무시합니다. `/mcp/readonly` 처럼 경로가 다르면 다른 서버로 보고 건드리지 않습니다.
  - 범위는 사용자 범위와 이 프로젝트의 로컬 범위입니다. 프로젝트 `.mcp.json` 은 커밋되는 파일이라 고치지 않고 경고만 보여 줍니다.
  - 플러그인 설정에 내 토큰이 있어야 합니다. 없으면 지우지 않고 「설정에 내 토큰을 넣으면 정리합니다」라고 알립니다.
  - 먼저 그 토큰으로 서버에 접속해 봅니다. 통과해야 지웁니다. 통과하지 못하면 기존 등록을 그대로 둡니다.
  - 지운 뒤에는 플러그인 연결로 도구를 하나 불러 확인합니다.
    - 확인에 성공하면 정리를 마쳤다고 알립니다.
    - 플러그인 연결은 됐는데 도구 호출이 실패하면, 지운 등록을 같은 설정으로 되살립니다.
    - 이 세션이 아직 플러그인 서버에 붙지 못했으면, 등록은 지운 채로 두고 다시 시작하라고 알립니다. 같은 주소의 수동 등록으로 시작한 세션은 대개 이 경우입니다. 다음 시작부터 플러그인 연결을 씁니다.
  - 이미 떠 있는 다른 세션은 기존 연결을 그대로 쓰다가, 다시 시작하면 바뀝니다.

## 신원 고르기

### 명령

| 명령 | 하는 일 |
|---|---|
| `/genia-works:login` | 로그인 화면을 엽니다. 등록된 AI 중에서 고르기, 새 AI 추가, 등록된 AI 관리(키 바꾸기·삭제)를 합니다. 등록된 AI 가 없으면 바로 「새 AI 추가」로 갑니다 |
| `/genia-works:as <이름>` | 화면 없이 바로 바꿉니다. `me` 를 주면 내 토큰으로 돌아갑니다. 이름 없이 실행하면 현재 신원과 등록된 이름을 보여 줍니다(키 값은 보여 주지 않습니다) |
| `/genia-works:logout` | **이 세션만** 내 토큰으로 되돌립니다(`/genia-works:as me` 와 같음). `GENIA_WORKS_AS` 로 띄운 세션이어도 내 토큰으로 갑니다. 등록한 키는 지우지 않습니다 |

- 바꾸면 이 세션의 genia-works 연결만 다시 붙습니다. 대화와 맥락은 그대로이고, 이후 genia-works 호출의 신원만 바뀝니다.
- `/clear` 를 해도 고른 신원은 유지됩니다. 세션을 끝내면(`/exit` 등) 선택이 지워집니다.
- 프롬프트 아래 상태 줄은 AI 신원을 쓰는 세션에서만 보입니다. 이때 `<이름>` 이 보이고, 그 이름의 키가 없으면 「<이름> 키가 없습니다 — /genia-works:login」이 보입니다. 앞의 플러그인 이름 genia-works 는 Claude Code 가 붙입니다. 내 토큰·`GENIA_WORKS_TOKEN` 으로 접속하면 상태 줄이 없습니다. 지금 신원과 「내 토큰 없음」 같은 설정 안내는 인자 없는 `/genia-works:as` 로 확인합니다.

### 띄울 때 고르기

```
GENIA_WORKS_AS=ai-dev claude
```

세션 안에서 고르기 전까지 이 세션은 `ai-dev` 로 접속합니다. 키는 미리 `/genia-works:login` 이나 터미널 명령으로 등록해 둡니다.

### 우선순위

가까운 것이 이깁니다.

1. 세션 안 선택(`/genia-works:login`, `/genia-works:as`)
2. `GENIA_WORKS_AS=<이름>`
3. 내 토큰 — `GENIA_WORKS_TOKEN` 환경변수가 있으면 그 값, 없으면 플러그인 설정의 `token`

- 「내 토큰으로 돌아가기」(`/genia-works:logout`, `/genia-works:as me`, 로그인 화면의 「내 토큰」)는 「내 토큰」을 세션 안 선택(1번)으로 고르는 것이라 `GENIA_WORKS_AS` 보다 먼저 적용돼 3번으로 갑니다. 로그인 화면의 이 버튼은 `GENIA_WORKS_TOKEN` 이 있으면 「내 토큰 (환경변수 GENIA_WORKS_TOKEN)」으로 보입니다. 그래서 **`GENIA_WORKS_TOKEN` 을 주고 띄운 세션이면 그 환경변수 값으로** 돌아갑니다.
- **고른 이름의 키가 없으면 접속이 실패합니다.** 키가 없거나 형식이 깨진 이름을 고르면 서버가 거절하는 값으로 접속합니다. 그래서 `/mcp` 에 실패로 보이고, 상태 줄에 「<이름> 키가 없습니다 — /genia-works:login」이 뜹니다. 조용히 내 토큰으로 바뀌지는 않습니다. AI 로 일한다고 믿었는데 기록이 내 이름으로 남는 일을 막기 위해서입니다.
  - 다른 세션이 쓰던 AI 키를 관리 화면에서 지우면, 그 세션도 다음에 다시 연결할 때 실패로 보입니다.
- `me` 는 「내 토큰」을 뜻하는 예약 이름입니다. AI 이름으로 쓸 수 없습니다.

### 새 AI 추가

1. 관리자 › 에이전트에서 외부 실행 AI 의 키(`ak_…`)를 발급받습니다.
2. `/genia-works:login` › 「새 AI 추가」에서 키를 붙여 넣고, 이름에 그 AI 의 아이디를 적습니다.
3. 저장하기 전에 플러그인이 그 키로 서버에 접속해 봅니다. 거절되면 저장하지 않습니다. 같은 이름이 있으면 바꿀지 한 번 더 묻습니다.
4. 저장한 뒤 「바꾸기」를 누르면 이 세션이 그 AI 로 접속합니다.

키 칸은 입력을 ● 로 가립니다. 다만 가림은 흉내입니다. 친 글자는 한 화면 갱신 동안 평문으로 그려진 뒤 ● 로 바뀝니다. 붙여 넣으면 **붙여 넣은 키 전체**가 그렇게 그려집니다. 대화 기록·명령 기록·디버그 로그에는 남지 않지만, 화면 녹화에는 잡힐 수 있습니다. 화면을 녹화하거나 공유 중이면 아래 터미널 명령을 쓰세요.

### 터미널로 키 넣기

로그인 화면 아래에 실제 경로가 들어간 명령이 보입니다.

```
"<플러그인 경로>/scripts/gw-set-key" ai-dev
```

키를 붙여 넣고 Enter 를 누릅니다. 화면에 보이지 않고(`stty -echo`) 셸 기록에도 남지 않습니다. 넣은 뒤 `/genia-works:as ai-dev` 로 바꿉니다.

이 명령은 서버 확인 없이 형식(`ak_` + 영문·숫자·`_-`)만 검사하고 저장합니다. 틀린 키면 바꿨을 때 `/mcp` 에 실패로 보입니다.

## 이슈 작업 보고 스킬

`/genia-works:work-on <이슈 키>`(예: `/genia-works:work-on WP-377`)로 부릅니다. 「WP-377 작업해」처럼 말해도 Claude 가 이 스킬을 씁니다.

- 시작할 때 이슈를 읽고 `report_agent_work` 로 「작업 중」을 보고합니다. 이슈가 할 일이면 서버가 진행 중으로 바꿉니다.
- 일하는 동안 단계·한 줄 메모를 갱신하고, 사용자에게 물을 때는 「답변 필요」로 바꾼 뒤 이슈 챗에서 답을 읽습니다.
- 담당자 없는 하위 이슈가 있으면 함께 맡을지 묻습니다.
- 끝낼 때는 아래 마무리 스킬 절차를 따릅니다.

보고는 그 이슈의 담당자만 할 수 있습니다. AI 신원으로 접속한 세션이면 그 AI 이름으로 보고됩니다.

## 이슈 작업 마무리 스킬

`/genia-works:work-done <이슈 키> [검토|완료|취소|실패|반려]`(예: `/genia-works:work-done WP-377 검토`)로 부릅니다. 「WP-377 마무리해」처럼 말해도 됩니다. work-on 으로 일하다 끝낼 때도 이 절차를 씁니다.

- 커밋·머지 커밋, 바뀐 범위, 테스트 결과, 스스로 정한 것, 남은 일을 모아 요약합니다.
- 끝낼 방식을 주지 않으면 요약을 보여 주고 묻습니다. 답이 안 온 질문이나 열린 하위 이슈가 있으면 함께 알립니다.
- 검토 대기는 「검토 대기」로, 완료는 요약을 남긴 뒤 이슈를 DONE 으로(그때 작업도 완료로 닫힙니다), 취소·반려·실패는 작업만 끝내고 이슈는 열어 둡니다. 요약은 이슈 챗에 남습니다.
- 그 세션이 이슈를 하려고 만든 워크트리·브랜치·로컬 스택·임시 파일을 정리합니다. 지우기 전에 무엇을 지우고 남길지 보여 주고, 아직 main 에 없거나 커밋 안 된 것은 묻습니다.

## 자동으로 이슈 처리하기 (work-loop)

AI 에게 이슈를 할당해 두면, 그 AI 가 자기 이슈를 하나씩 가져와 사람 손 없이 처리합니다. 구현 → 리뷰 → 커밋 하나로 합치기 → 브랜치 라이브 검증 → main 머지까지 마친 뒤 「검토 대기」로 올립니다. push·태그·배포는 하지 않고, 이슈 완료(DONE) 처리는 본문이 시킨 경우에만 합니다. 사람이 검토 대기 이슈를 보고 정합니다.

저장소 폴더에 터미널을 하나 따로 열고 AI 신원으로 띄운 뒤 반복을 걸어 둡니다.

```
GENIA_WORKS_AS=<AI 이름> claude --permission-mode bypassPermissions
/loop /genia-works:work-loop <프로젝트 키>
```

- `/genia-works:work-loop <프로젝트 키>` 만 부르면 한 번만 돕니다(시험·수동 실행용).
- 한 번 부를 때마다 이슈 하나를 멈출 지점(검토 대기·질문·막힘·다음 회차 대기)까지 처리합니다. 할 일이 더 있으면 1분쯤 뒤, 없으면 20~30분 뒤(그보다 이른 다음 회차 시각이 있으면 그 시각)에 다시 확인합니다.
- 명확하지 않은 것(UI/UX·아키텍처·설계·접근 방안)만 이슈 챗으로 묻고, 답을 기다리는 동안 다음 이슈로 넘어갑니다. 이슈 챗에 답을 남기면 다음 확인 때 이어서 합니다. 그 밖의 결정은 스스로 내리고 검토 대기 보고에 「내가 정한 것」으로 모읍니다.
- 담당자 없는 하위 이슈가 있으면 맡을지 먼저 묻고, 맡은 하위를 하나씩 처리합니다. 하위가 모두 검토 대기가 되면 부모를 검토 대기로 올립니다.
- 멈추게 하려면 그 이슈의 이슈 챗에 멈추라고(또는 그만두라고) 남깁니다. AI 가 다음 확인 때 읽고 작업을 「일시 중지」로 바꿉니다. work-loop 는 작업을 끝냄(취소·반려·실패)으로 닫지 않습니다 — 할 수 없거나 실패한 일은 「막힘」으로 이유와 함께 남깁니다.
- 다시 하게 하려면 그 이슈의 이슈 챗에 다시 해 달라고 남깁니다. 다음 확인 때 읽고 이어 합니다. 막힘·답변 필요 이슈도 이슈 챗에 글을 남기면 다음 확인 때 읽고 이어 합니다.
- 회차로 나눠 이어 가라는 이슈 본문의 지시를 따릅니다 — 아래 「반복 업무 맡기기」.
- 사람처럼 이슈를 만들고 담당자를 정합니다 — 일을 나눠 다른 AI·사람에게 맡기거나 찾은 결함을 등록합니다. 담당자를 넣거나 뺄 때는 이유를 그 이슈에 댓글로 남깁니다. 받은 AI 는 자기 work-loop 의 다음 확인 때 이어 받습니다.

### 반복 업무 맡기기 (본문 지시)

AI 를 담당자로 둔 에픽 본문에 회차의 정의를 적어 두면, work-loop 가 그날 하위를 만들어 처리하고 마감이 지난 하위를 닫으며 이어 갑니다. 정해진 양식은 없고, 아래는 참고용 예시입니다.

```markdown
## 지속 업무 — AI 결함 탐색
- 주기: 평일 09:00 에 그날 하위 이슈를 만든다(이미 있으면 만들지 않는다)
- 하위 제목: 결함 탐색 — {월/일}, 우선순위 HIGH, 마감 그날
- 하위 한 회차: 아직 안 본 기능 영역 하나를 탐색적 테스트한다(최대 60분)
- 찾은 결함은 버그 이슈로 등록한다(라벨 `AI 탐색`, 본문에 발견한 하위 키). 같은 결함이 이미 있으면 등록하지 않는다
- 하위는 그날 할 일을 마치면 결과 요약(본 영역·등록한 버그)을 남기고 닫는다. 마감이 지난 열린 하위도 닫는다
```

- 이슈 닫기는 사람이 만든 이슈의 본문이 시킬 때만, 그 지시로 만든 하위와 그 이슈 자신에 한해 합니다. AI 가 만든 하위의 본문으로는 닫지 않습니다.
- push·배포·검증 전 머지 금지 같은 규칙은 본문으로 바꿀 수 없고, 코드를 바꾼 회차는 닫지 않고 검토 대기로 올립니다.
- 처음 지시를 따를 때 「본문을 이렇게 이해했다」를 이슈 챗에 남깁니다. 다르면 본문을 고치거나 이슈 챗으로 알려 주세요. 필요한 것이 본문에서 분명하지 않으면 묻습니다.
- 다음 회차를 기다리는 동안 에픽은 「다음 회차 대기」로 보이고, 그 사이 다른 이슈를 처리합니다. 에픽은 검토 대기로 올리지 않으니, 그만두려면 사람이 닫거나 멈추라고 남깁니다.

### 꼭 알아 둘 것

- **AI 신원 세션에서만 돕니다.** 내 토큰으로 접속한 세션에서 부르면 아무 이슈도 건드리지 않고 `/genia-works:as <AI 이름>` 으로 바꾸라고 안내한 뒤 멈춥니다.
- **`/loop` 제약**: Claude Code 가 열려 있고 쉬는 동안만 돕니다. 반복은 7일 뒤 만료되니 다시 걸어 주세요.
- **권한 모드**: 확인 창에 멈추지 않으려면 `--permission-mode bypassPermissions` 로 띄웁니다. 이 모드는 확인 없이 무엇이든 실행하므로 **이 AI 전용 세션에서만** 쓰세요. 키 파일 보호(키 저장소 경로를 가리키는 도구 호출 막기)는 이 모드에서도 플러그인이 계속 막습니다.
- **superpowers 권장**: [superpowers](https://github.com/obra/superpowers) 플러그인(`/plugin install superpowers@claude-plugins-official`)이 있으면 설계·계획·구현을 그 스킬로 더 꼼꼼하게 합니다. 없어도 기본 절차로 돌고, 첫 실행에 한 번 설치를 안내합니다.
- **`.work-loop/project.md` 필요**: 저장소마다 다른 것(바뀐 범위별 테스트 명령, 격리 로컬 스택을 띄우고 내리는 방법, 건드리면 안 되는 포트)을 이 파일에 적어 커밋해 둡니다. 없으면 라이브 검증 단계에서 「막힘」으로 멈춥니다.
- **`.work-loop/state/` 는 git 무시**: 잠금(`loop.lock`)·작업 메모·검증 스크린샷 같은 실행 상태를 둡니다. `.gitignore` 에 `.work-loop/state/` 를 넣으세요.
- 저장소 폴더 하나에는 work-loop 하나만 돕니다. 같은 폴더에서 실수로 두 번 띄우면 나중 것은 아무것도 하지 않고 끝납니다. AI 여럿이 서로 일을 넘기며 같은 저장소를 다루게 하려면 AI 마다 저장소를 따로 clone 해 그 폴더에서 띄웁니다(다른 PC 여도 됩니다).
- 작업은 이슈마다 워크트리(`.claude/worktrees/<이슈 키>`, 브랜치 `ai/<이슈 키>`)에서 합니다. main 작업 폴더의 브랜치는 바꾸지 않고, 머지는 그 폴더가 `main` 이고 겹치는 수정 중 파일이 없을 때만 합니다.

## 키 저장 위치

| 경로 | 내용 | 권한 |
|---|---|---|
| `~/.genia-works/keys/<이름>` | AI 키 한 줄. 등록 날짜는 파일 수정 시각 | 파일 600, 폴더 700 |
| `~/.genia-works/sessions/<claude 프로세스 번호>-<시작 시각>` | 그 세션이 고른 이름(또는 `me`) | 파일 600, 폴더 700 |

- 이름은 영문·숫자·`._@-` 만 씁니다. 키는 `ak_` 로 시작하고 영문·숫자·`_-` 로만 이뤄져야 합니다.
- 플러그인 폴더는 버전마다 바뀌므로 키를 홈 폴더에 둡니다. 저장소 밖이라 커밋될 일이 없고, 워크트리에서도 같은 키를 씁니다.
- 끝난 세션의 선택 파일은 다음 접속 때 자동으로 지워집니다.

### 남는 위험

| 위험 | 플러그인이 하는 일 | 남는 것 |

| 붙여 넣은 키가 Claude 입력창으로 들어감 | 로그인 화면 안에서 화면이 바뀔 때마다 포커스를 새 화면의 첫 칸(새 AI 추가면 키 칸)으로 옮깁니다. 패널이 키보드를 잃은 채 추가 화면이 보이면 「이 패널에 키보드가 없습니다」 경고를 먼저 보입니다 | 「＋ 새 AI 추가」에서 Enter 와 붙여넣기가 거의 동시에(버튼이 눌려 처리되기 전에) 들어오면 키가 입력창으로 갈 수 있습니다. 그 틈은 기계가 바쁠수록 길어집니다. 그때는 Enter 를 누르지 말고 지운(Ctrl+U) 뒤 ctrl+x tab 으로 패널에 와서 다시 붙여 넣으세요 |

| AI 로 접속한 줄 모르고 일함 | AI 로 접속한 세션은 상태 줄에 그 이름을 늘 보여 줍니다. 키가 없으면 내 토큰으로 바꾸지 않고 실패시킵니다 | — |

## 제한

- **Windows**: 신원을 고르는 스크립트가 POSIX sh 라 돌지 않습니다. 내 토큰(플러그인 설정)과 환경변수 대체 경로만 씁니다. AI 로 접속하려면 띄울 때 키를 환경변수로 줍니다.
  ```
  GENIA_WORKS_TOKEN=<발급한 ak_ 키> claude
  ```
  이 방법은 셸 기록에 키가 남을 수 있습니다. 환경변수를 셸 기록이 남지 않는 방법으로 설정하세요.
- **`claude -p`(비대화형)**: 로그인 화면을 그릴 수 없고, 연결을 다시 붙일 수 없어 신원을 바꿀 수 없습니다. `/genia-works:as <이름>`·`logout` 은 「이 세션에서는 바꿀 수 없습니다」, `login` 은 「대화형 세션에서만 열 수 있습니다」라고 답하고 아무것도 바꾸지 않습니다. 띄울 때 `GENIA_WORKS_AS=<이름>` 이나 `GENIA_WORKS_TOKEN` 으로 정하세요.
- 신원은 연결할 때 정해집니다. 바꾸면 이 세션의 genia-works 연결이 다시 붙습니다. Claude 가 genia-works 도구를 부르는 중에는 바꾸지 마세요.

## 업데이트

자동 업데이트는 기본으로 꺼져 있습니다.

- 새 버전 받기: `/plugin marketplace update genia-works`
- 자동 업데이트 켜기: `/plugin` › Marketplaces › genia-works

## 개발

```
claude --plugin-dir plugins/genia-works   # 설치 없이 이 폴더로 띄우기(사용자 설정을 바꾸지 않음)
pnpm test:plugin                          # 스크립트·순수 함수 테스트(node --test)
claude plugin test plugins/genia-works    # mod 테스트(tests/mod.test.ts)
claude plugin validate plugins/genia-works
```

- `--plugin-dir` 로 띄워도 `/plugin configure` 로 넣은 값은 사용자 설정(`pluginConfigs["genia-works@inline"]`)에 저장됩니다. 로컬 서버로 시험할 때는 폴더를 복사해 `plugin.json` 의 `server_url` 기본값을 바꾸고, 내 토큰은 `GENIA_WORKS_TOKEN` 환경변수로 주면 사용자 설정이 바뀌지 않습니다.
- `scripts/` 의 스크립트는 `bin/` 에 두지 않습니다. `bin/` 은 Bash 도구의 PATH 에 들어가 Claude 가 이름만으로 헤더 스크립트를 실행해 키를 출력할 수 있게 됩니다.
- mod(`hooks/register.js`)는 `$` 를 쓰는 코드를 그 파일 안에만 둡니다. 순수 함수는 `hooks/lib.js` 에 둡니다.

## 릴리스

마켓플레이스 목록 파일(`apps/workplace-web/public/claude/marketplace.json`)은 이 폴더를 릴리스 태그로 가리킵니다. main 에 들어간 변경이 사용자에게 바로 나가지 않게 하려는 것입니다.

1. `.claude-plugin/plugin.json` 의 `version` 을 올립니다.
2. 태그 `genia-works--v<버전>` 을 달고 올립니다.
3. 목록 파일의 `ref` 를 그 태그로 바꾸고 웹을 배포합니다.
