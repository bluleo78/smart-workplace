# 테넌트 정지·활성화와 삭제

테넌트를 잠시 막을 때는 정지하고, 그만 쓰게 된 테넌트는 삭제합니다. 정지와 삭제는 모두 되돌릴 수 있습니다. 삭제한 테넌트의 데이터를 완전히 지우는 영구 삭제만 되돌릴 수 없습니다.

> **이 장에서 할 수 있는 일**
>
> - 테넌트를 정지하고 다시 활성화합니다.
> - 테넌트를 삭제하고 복원합니다.
> - 삭제한 테넌트를 영구 삭제하고 진행 상태를 봅니다.

| 하는 일 | 할 수 있는 상태 | 결과 | 되돌리기 |
| --- | --- | --- | --- |
| 정지 | **활성** | **정지됨** | 활성화 |
| 활성화 | **정지됨** | **활성** | 다시 정지 |
| 삭제 | **활성**·**정지됨** | **삭제됨** | 복원(**활성** 으로 돌아옴) |
| 복원 | **삭제됨** | **활성** | 다시 삭제 |
| 영구 삭제 | **삭제됨** | **영구 삭제 중…** → 목록에서 사라짐 | 되돌릴 수 없음 |

## 테넌트를 정지한다

정지하면 구성원이 그 테넌트(워크스페이스)에 들어갈 수 없게 됩니다. 구성원의 계정이 막히는 것은 아니어서, 다른 테넌트에도 소속된 구성원은 그곳에서 그대로 일합니다. 그 테넌트에만 소속된 구성원은 로그인하면 사용자 앱에 「접속 가능한 워크스페이스가 없습니다. 관리자에게 문의하세요.」라는 안내가 나옵니다. 정지된 테넌트에서는 다음이 막힙니다.

- 구성원이 그 테넌트(워크스페이스)로 들어가는 것
- 이미 그 테넌트에 들어와 있던 구성원의 다음 요청부터 모든 요청
- 그 테넌트에서 발급한 API 키·외부 AI 도구 연결
- 그 테넌트의 공유 링크(드라이브 공유 링크, 노트 공개 링크, 캘린더 구독 주소)

데이터는 그대로 남고, 정지한 동안에도 콘솔에서 정보 편집·드라이브 용량 한도 변경·구성원 추가는 할 수 있습니다.

![활성 테넌트의 상세 화면 — 정지 단추](shots/operator/tenant-lifecycle-1.png){crop=card marks=suspend}

1. 테넌트 상세 화면 오른쪽 위의 **정지** 를 누릅니다. **테넌트 정지** 확인 창이 열립니다.
2. 확인 창의 **정지** 를 누릅니다. 상태가 **정지됨** 으로 바뀝니다.

콘솔은 정지 사유를 적는 칸이 없고 소유자에게 알림도 보내지 않습니다. 정지하기 전에 소유자에게 콘솔 밖에서 따로 알립니다.

## 정지한 테넌트를 다시 활성화한다

정지된 테넌트의 상세 화면에는 **정지** 대신 **활성화** 가 보입니다.

![정지된 테넌트의 상세 화면 — 상태와 활성화 단추](shots/operator/tenant-lifecycle-2.png){crop=card marks=status,activate}

1. 상태가 **정지됨** 인지 확인합니다.
2. **활성화** 를 누릅니다. **테넌트 활성화** 확인 창이 열립니다.
3. 확인 창의 **활성화** 를 누릅니다. 상태가 **활성** 으로 바뀌고 구성원이 다시 들어올 수 있습니다.

## 테넌트를 삭제한다

삭제는 테넌트를 쓰지 않게 치워 두는 것입니다. 데이터는 지워지지 않고, 영구 삭제하기 전까지 언제든 복원할 수 있습니다. 삭제하면 구성원이 그 테넌트(워크스페이스)에 바로 들어갈 수 없게 되고, 정지와 같은 것이 모두 막힙니다. 다른 테넌트에도 소속된 구성원은 그곳에서 그대로 일합니다. 그 테넌트에만 소속된 구성원이 로그인하면 정지했을 때와 같은 안내가 나옵니다. 정보 편집·드라이브 용량 한도 변경·구성원 추가도 할 수 없게 됩니다.

### 위험 구역에서 삭제를 누른다

삭제는 테넌트 상세 화면 맨 아래의 **위험 구역** 에 있습니다.

![위험 구역 — 삭제 단추](shots/operator/tenant-lifecycle-3.png){crop=danger marks=delete}

1. **위험 구역** 의 **삭제** 를 누릅니다. 확인 창이 열립니다.

기본 테넌트 「Default Workspace」 는 **위험 구역** 에 **기본 테넌트는 신규 가입자가 들어가는 곳이라 삭제할 수 없습니다.** 라는 안내가 나오고 **삭제** 가 흐리게 보입니다.

### 확인 창에서 삭제를 확정한다

![삭제 확인 창 — 대상 테넌트 이름이 제목에 나옵니다](shots/operator/tenant-lifecycle-4.png){crop=dialog marks=confirm}

1. 창 제목의 테넌트 이름이 지우려는 테넌트인지 확인하고 **삭제** 를 누릅니다.

삭제한 테넌트는 목록의 **운영 중** 에서 빠지고 **삭제됨** 으로 옮겨집니다.

> **주의**
>
> 삭제를 확정하는 순간 그 테넌트의 구성원은 모두 그 테넌트에 들어갈 수 없게 됩니다. 일하는 중인 구성원이 있는지 먼저 소유자와 확인합니다.

## 삭제한 테넌트를 복원한다

삭제된 테넌트의 상세 화면 맨 위에는 삭제된 날짜와 함께 삭제된 테넌트라는 안내가 나옵니다.

![삭제된 테넌트의 상세 화면 — 안내와 복원 단추](shots/operator/tenant-lifecycle-5.png){crop=banner+card marks=restore}

1. 안내 오른쪽의 **복원** 을 누릅니다. 확인 창 없이 바로 복원되고, 상태가 **활성** 으로 바뀝니다.

정지된 채로 삭제했던 테넌트도 복원하면 **활성** 이 됩니다. 계속 막아 두어야 하면 복원한 뒤 다시 정지합니다.

## 삭제한 테넌트를 영구 삭제한다

영구 삭제는 삭제된 테넌트의 데이터를 완전히 지웁니다. 지우는 것과 남는 것은 다음과 같습니다.

| 지워짐 | 남음 |
| --- | --- |
| 이슈·메일·드라이브·노트 등 그 테넌트의 모든 데이터와 파일, 그 테넌트 전용 AI 에이전트, 테넌트 자체 | 사용자 계정(그 테넌트 소속만 풀림). 다른 테넌트에도 소속된 구성원은 그 테넌트에서 그대로 일합니다 |

> **경고**
>
> 영구 삭제는 되돌릴 수 없습니다. 진행 중에는 복원할 수 없고, 지운 데이터와 파일은 다시 꺼낼 수 없습니다. 데이터를 지우기 전 단계에서 실패한 경우에만 **삭제됨** 으로 돌아옵니다(아래 「영구 삭제가 실패했을 때」).

### 이름을 입력해 영구 삭제를 시작한다

삭제된 테넌트의 **위험 구역** 에는 **삭제** 대신 **영구 삭제** 가 있습니다. **영구 삭제** 를 누르면 지울 테넌트의 이름을 묻는 확인 창이 열립니다.

![영구 삭제 확인 창 — 테넌트 이름을 입력해야 단추가 켜집니다](shots/operator/tenant-lifecycle-7.png){crop=dialog marks=input,confirm@br}

1. 입력 칸에 테넌트 이름을 그대로 입력합니다. 영문 대문자·소문자를 구분합니다.
2. **영구 삭제** 를 누릅니다. 이름이 정확히 같아야 단추가 켜집니다.

### 영구 삭제 진행 상태를 본다

영구 삭제는 백그라운드에서 진행됩니다. 진행하는 동안 상세 화면 맨 위에 진행 안내가 나오고, 상태는 **영구 삭제 중…** 입니다.

![영구 삭제 진행 중인 테넌트 — 진행 안내와 상태](shots/operator/tenant-lifecycle-8.png){crop=banner+card marks=banner,status}

1. 맨 위의 안내로 영구 삭제가 진행 중인지 확인합니다. 이때는 복원·편집 등 할 수 있는 일이 없고, **위험 구역** 도 보이지 않습니다.
2. 상태가 **영구 삭제 중…** 인지 확인합니다.

상세 화면을 열어 두면 몇 초마다 진행을 다시 확인합니다. 끝나면 **영구 삭제가 완료되었습니다.** 라는 알림과 함께 목록의 **삭제됨** 으로 돌아가고, 테넌트는 목록에서 사라집니다.

### 삭제된 테넌트를 목록에서 본다

![삭제됨 보기 — 삭제된 테넌트와 영구 삭제 중인 테넌트](shots/operator/tenant-lifecycle-6.png){crop=header+table marks=toggle,rows}

1. 테넌트 목록 위의 **삭제됨** 을 누릅니다.
2. 목록에서 테넌트의 상태(**삭제됨**·**영구 삭제 중…**)와 **삭제일** 을 확인합니다.

### 영구 삭제가 실패했을 때

영구 삭제는 데이터를 지우는 단계에서 실패하면 아무것도 지우지 않은 채 되돌아갑니다. 이때 테넌트는 다시 **삭제됨** 이 되고, 안내에 **지난 영구 삭제 실패:** 와 사유가 나옵니다. **위험 구역** 의 단추는 **영구 삭제 다시 시도** 로 바뀝니다. 사유를 확인한 뒤 다시 시도하거나, 필요하면 복원합니다.

데이터를 지운 뒤 마무리 단계에서 실패하면 **영구 삭제 중…** 상태가 그대로 유지되고, 안내에 **마지막 시도 오류:** 와 사유가 나옵니다. 영구 삭제는 잠시 뒤 자동으로 다시 시도됩니다.

삭제한 테넌트는 삭제일부터 30일 동안 보관합니다. 그동안은 복원할 수 있고, 30일이 지나면 슈퍼어드민이 영구 삭제를 시작합니다. 영구 삭제는 자동으로 시작되지 않으므로 **삭제일** 을 보고 직접 시작합니다.
