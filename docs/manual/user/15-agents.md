# AI 에이전트 관리

에이전트는 워크스페이스의 AI 구성원입니다. 사람처럼 이슈 담당자가 되고(4장), 대화에서 멘션을 받고, 맡은 일을 합니다. 관리자는 **설정** → **에이전트** 에서 에이전트를 만들고, 실행 방식과 AI 계정을 정하고, 워크스페이스 공통 비서를 지정합니다. 개발을 맡길 AI 는 Works 가 직접 작업 공간을 띄워 돌리게 할 수 있고, 그 작업 공간이 뜰 곳은 같은 화면의 **실행 환경** 탭에서 정합니다.

> **이 장에서 할 수 있는 일**
>
> - 에이전트 목록을 보고 새 에이전트를 만듭니다.
> - 에이전트 상세에서 이름·맡은 일·지시·역할·사용 상태를 바꿉니다.
> - 실행 방식(**기본**·**Claude Code**·**외부**)을 고르고 AI 계정을 연결합니다.
> - 공통 비서를 지정하고, 외부 도구로 일할 에이전트에 접속 키를 발급합니다.
> - Claude Code 로 도는 에이전트의 실행을 시작하고 멈추고, 작업 설정을 바꿉니다.
> - AI 가 돌 실행 환경을 만들고 관리합니다.

## 설정 가이드를 함께 본다

에이전트 화면의 설명과 주의 사항은 화면 오른쪽 **설정 가이드** 에 모여 있습니다. 머리의 **가이드** 를 누르면 열립니다. 에이전트 상세에서는 가이드가 섹션별로 나뉘어 있어, 본문을 내리면 지금 보고 있는 섹션의 안내로 따라 바뀝니다. 외부 도구를 연결하는 명령도 이 가이드에 있습니다.

## 에이전트 목록을 본다

**설정** → **에이전트** 를 열면 **목록** 탭이 보입니다.

1. **개인 비서 표시** 를 켜면 구성원이 12장에서 만든 개인 비서도 목록에 함께 보입니다.
2. 새 에이전트를 만들려면 머리의 **+ 새 에이전트** 를 누릅니다.
3. 행마다 이름·**아이디**·**유형**·**실행**·**생성일** 이 보입니다. 행을 누르면 그 에이전트의 상세 화면으로 갑니다.

에이전트가 하나도 없거나 공통 비서가 없으면 목록 위에 지금 할 일이 노란 띠로 보입니다.

**유형** 은 셋입니다.

| 유형 | 뜻 |
| --- | --- |
| **공통** | 워크스페이스 공통 비서. 개인 비서가 없는 구성원의 AI 어시스턴트를 맡습니다 |
| **개인** | 구성원 한 사람의 개인 비서. 옆에 주인 이름이 보입니다 |
| **일반** | 이슈 담당 같은 일을 맡기는 에이전트 |

**실행** 열에는 실행 방식이 보입니다. **기본** 은 Works 가 이슈·멘션에 바로 답하는 에이전트, **Claude Code** 는 Works 가 작업 공간을 띄워 돌리는 에이전트, **외부** 는 사람이 직접 띄운 AI 도구가 접속 키로 접속해 일하는 에이전트입니다. 외부 에이전트에는 키를 마지막으로 쓴 시각이 함께 보입니다.

Claude Code 로 도는 에이전트는 배지 옆에 지금 상태가 보이고, 화면을 새로 고치지 않아도 바뀝니다.

| 상태 | 함께 보이는 것 |
| --- | --- |
| **작업 중** · **막힘** | 처리 중인 이슈 키(누르면 이슈로 갑니다) |
| **쉬는 중** | 다음에 할 일을 확인할 시각 |
| **실패** | 실패한 까닭 한 줄 |
| **시작하는 중** · **멈추는 중** · **꺼짐** | — |

기본 실행 환경이 아닌 곳에서 돌면 실행 환경 이름도 함께 보입니다.

**새 에이전트** 창에서 **아이디**·**이름**·**이메일** 을 넣고 **생성** 을 누르면 에이전트가 만들어집니다.

## 에이전트 상세를 연다

목록에서 행을 누르면 에이전트 상세 화면이 열립니다. 머리 왼쪽의 뒤로 가기 단추를 누르면 목록으로 돌아갑니다. 상세는 위에서부터 다음 섹션으로 나뉩니다.

| 섹션 | 하는 일 |
| --- | --- |
| **상태** | 사용 여부와 지금 하는 일, 실행 시작·멈춤 |
| **기본 정보** | 아바타·**이름**·**아이디** |
| **역할 할당** | 이 AI 에게 줄 역할 |
| **맡은 일과 지시** | 다른 AI 가 읽는 설명과 이 AI 가 따르는 규칙 |
| **실행** | 실행 방식, AI 계정, 작업 설정, 접속 키 |
| **코드 저장소** | 이 AI 가 맡는 프로젝트 |
| **위험 구역** | 에이전트 삭제 |

개인 비서는 주인이 관리하므로 이름·맡은 일·지시를 바꿀 수 없고, **역할 할당** 과 **위험 구역** 이 없습니다.

## 에이전트 정보를 바꾼다

1. **기본 정보** 에서 **이름** 과 **아이디** 를 고치고 **저장** 을 누릅니다. 아이디는 @멘션과 외부 도구의 접속에 쓰이므로, 바꾸면 예전 아이디로 한 멘션은 이 AI 에게 가지 않습니다.
2. **역할 할당** 에서 역할을 고르고 저장합니다. AI 에게는 관리자 역할이나 관리 권한이 든 역할을 줄 수 없습니다.
3. **맡은 일과 지시** 의 **맡은 일** 에 이 AI 가 무엇을 맡는지 적습니다. 다른 AI 가 일을 맡길 상대를 고를 때 이 설명을 읽습니다.
4. **지시** 에는 이 AI 가 일할 때마다 따를 규칙을 적고 **저장** 을 누릅니다. 실행 방식이 **기본** 인 AI 는 지시를 읽지 않습니다.

## 에이전트 사용을 멈춘다

**상태** 의 **사용** 스위치를 끄면 확인 창이 뜨고, 확인하면 그 AI 는 이 워크스페이스에 접속하거나 일할 수 없습니다. 실행 중이던 AI 는 실행도 멈춥니다. 다시 켜도 실행은 직접 시작해야 합니다.

공통 비서는 지정을 먼저 풀어야 사용을 멈출 수 있습니다. 개인 비서의 스위치는 주인이 관리하므로 여기서 바꿀 수 없습니다.

## 실행 방식을 고른다

**실행** 섹션 맨 위의 **실행 방식** 카드 셋 가운데 하나를 고릅니다.

| 카드 | 뜻 |
| --- | --- |
| **기본** | Works 가 실행하고, 이슈·멘션에 바로 답합니다. AI 계정을 연결해야 일합니다 |
| **Claude Code** | Works 가 실행 환경에 이 AI 의 작업 공간을 띄워, 맡은 이슈를 개발·테스트하고 PR 까지 올립니다 |
| **외부** | 사람이 직접 띄운 AI 도구가 이 AI 의 접속 키로 접속해 일합니다 |

1. 바꿀 카드를 누릅니다. 카드를 누르기만 해서는 바뀌지 않고, 그 방식에 필요한 칸이 아래에 펼쳐집니다.
2. **Claude Code** 면 펼쳐진 작업 설정(모델·대기열 라벨·실행 환경)을 채웁니다.
3. **바꾸기** 를 누릅니다. 확인 창에 바꾸면 무엇이 달라지는지(지워지는 설정, 폐기되는 키 등)가 보입니다.
4. 확인 창의 **바꾸기** 를 누르면 저장됩니다.

공통 비서와 개인 비서는 서버에서 대화해야 하므로 **기본** 으로만 돕니다. 실행 중인 AI 는 먼저 실행을 멈춰야 방식을 바꿀 수 있습니다.

## AI 계정을 연결한다

**기본** 과 **Claude Code** 방식은 **실행** 섹션의 **AI 계정** 에서 AI 서비스에 연결합니다. 연결 방식(예: Claude 구독), 등록일, 최근 사용 시각이 보이고, 아직 연결하지 않았으면 **연결하기** 를 누릅니다. 연결 방식은 Claude 구독 토큰 또는 OpenAI 호환 API 키입니다. **Claude Code** 는 Claude 계정이어야 합니다.

- **다시 연결** 은 토큰을 새로 넣고, **연결 끊기** 는 저장한 토큰·키를 폐기합니다. 연결을 끊으면 에이전트가 AI 를 부를 수 없게 됩니다.

개인 비서의 AI 계정은 주인이 자기 설정에서 정합니다(12장).

> **참고**
>
> 등록한 토큰·키 값은 다시 보이지 않습니다. 화면에는 연결 종류와 날짜만 보입니다.

## 공통 비서를 지정한다

**기본** 방식 에이전트의 **실행** 섹션에는 **공통 비서** 묶음이 있습니다. 스위치를 켜면 이 에이전트가 워크스페이스 공통 비서가 됩니다. 공통 비서는 개인 비서를 두지 않은 구성원의 **AI 어시스턴트** 와 홈 AI 비서를 맡습니다. 먼저 AI 계정을 연결해야 지정할 수 있고, 개인 비서는 공통 비서로 지정할 수 없습니다. 지정하면 그 아래에서 **모델** 과 **생각의 깊이**(**없음**·**보통**·**깊게**), **추천 질문 모델** 을 고릅니다. 추천 질문 모델은 추천·후속 질문을 만들 때만 쓰는 가벼운 모델입니다.

공통 비서 지정을 해제하면 개인 비서가 없는 구성원은 화면 위 **AI 어시스턴트** 단추와 AI 기능을 쓸 수 없게 됩니다. 이미 열려 있는 화면은 새로 고친 뒤에 바뀔 수 있습니다.

## Claude Code 로 실행한다

Claude Code 로 돌리면 사람이 컴퓨터를 켜 두고 AI 를 띄울 필요가 없습니다. 먼저 아래 「실행 환경을 만든다」로 실행 환경이 하나 있어야 합니다.

### 처음 실행한다

1. 위 「실행 방식을 고른다」로 **Claude Code** 로 바꿉니다.
2. **AI 계정** 에 Claude 계정을 연결합니다.
3. **코드 저장소** 에서 맡는 프로젝트를 확인합니다. 이 AI 가 멤버이고 저장소가 연결된 프로젝트만 맡습니다. 바꾸려면 프로젝트 멤버로 넣거나 뺍니다.
4. **상태** 의 확인 항목(**Claude 연결**·맡는 프로젝트·**실행 환경 여유**)이 모두 **통과** 인지 봅니다. 맡는 프로젝트가 하나도 없으면 실행을 시작할 수 없습니다.
5. **실행 시작** 을 누릅니다. 작업 설정을 고친 채라면 **저장하고 실행 시작** 이 보입니다. **시작하는 중** 을 거쳐 **쉬는 중** 이나 **작업 중** 으로 바뀝니다.

> **참고**
>
> Claude Code 로 도는 AI 의 접속 키는 Works 가 만들고 주기적으로 바꿉니다. **접속 키** 에 다음 교체 무렵이 보입니다.

### 실행 중인 AI 를 살핀다

**상태** 에 상태와 처리 중인 이슈, 실행 시간, 메모리 사용량, 실행 환경이 보입니다.

- **다시 시작** 은 작업 공간을 새로 띄웁니다. **실행 멈춤** 은 하던 일을 멈추고 끕니다.
- 실패하면 까닭이 한 줄 보이고 **다시 시작** 이 나옵니다.

### 실행 중에 작업 설정을 바꾼다

1. **실행** 의 **작업 설정** 에서 모델·대기열 라벨·실행 환경을 바꾸고 저장합니다.
2. **상태** 에 「바꾼 작업 설정은 쉴 때 적용돼요.」가 보입니다. 하던 일을 끊고 바로 바꾸려면 **지금 적용** 을 누릅니다. 일하는 중이면 확인 창이 뜨고, 다시 뜬 작업 공간이 하던 이슈를 이어 받습니다.

## 외부 도구에 접속 키를 준다

실행 방식이 **외부** 인 에이전트는 사람이 띄운 AI 도구(예: 개인 컴퓨터의 Claude Code)가 접속 키로 접속합니다. **상태** 에는 마지막으로 접속한 시각(「마지막 접속 5분 전」 등)이 보이고, 아직 접속한 적이 없으면 「아직 접속 안 함」이 보입니다.

1. **실행** 의 **접속 키** 에서 키 이름을 넣고 **키 발급** 을 누릅니다. 새 키는 이 창에서 한 번만 보이므로 복사해 둡니다.
2. **가이드** 를 열어 **② genia-works 플러그인 설치** 부터 차례로 따릅니다. 명령마다 복사 단추가 있습니다.
3. **④ 이 AI 로 로그인** 의 명령을 실행하고 「새 AI 추가」를 골라 1에서 복사한 키를 붙여 넣습니다. 이름은 이 AI 의 아이디로 넣습니다.
4. **⑤ 자동으로 이슈 처리** 의 명령을 따르면 이 AI 에게 할당된 이슈를 하나씩 가져와 처리합니다.

발급한 키는 목록에서 폐기할 수 있습니다. 폐기한 키로는 바로 접속할 수 없습니다.

> **주의**
>
> 접속 키는 발급할 때 한 번만 보입니다. 잃어버렸으면 폐기하고 새로 발급합니다.

## 실행 환경을 만든다

실행 환경은 Works 가 Claude Code AI 의 작업 공간을 띄우는 클러스터입니다. **설정** → **에이전트** 의 **실행 환경** 탭에 환경마다 이름, **기본** 배지, **연결**(**연결됨**·**끊김**·**설치 대기**), 쓰는 AI, **최대 AI 수**(실행 중인 AI 수와 상한)가 보입니다.

1. 머리의 **+ 실행 환경 추가** 를 누릅니다.
2. **이름**·**설명 (선택)**·**최대 AI 수** 를 넣습니다. 최대 AI 수는 이 실행 환경에서 동시에 띄울 수 있는 AI 수입니다.
3. **추가하고 토큰 발급** 을 누르면 연결 토큰과 설치 순서가 보입니다. 토큰을 복사해 파일로 저장합니다.
4. 클러스터 담당자가 안내된 순서대로 연결 프로그램을 설치합니다. 설치가 끝나면 1분쯤 뒤 **연결됨** 으로 바뀝니다.

### Works 에 내부 IP 로 접속하는 클러스터

사내 클러스터처럼 Works 주소에 공인 주소로 닿지 못하고 내부 IP 로 가야 하는 곳이면, 설치 순서 위의 **Works 에 내부 IP 로 접속하는 경우 (선택)** 칸에 그 IP 를 넣습니다. 설치 명령에 Works 주소를 그 IP 로 푸는 값이 더해지고, 연결 프로그램과 그 프로그램이 띄우는 AI 작업 공간 모두에 들어갑니다. 칸을 비우면 명령은 그대로입니다.

**설치 대기** 가 오래 가면 설치 순서 아래의 **연결이 안 될 때 연결 프로그램 기록 보기** 명령으로 기록을 봅니다. fetch failed 가 거듭 보이면 그 클러스터에서 Works 주소에 닿지 못하는 것이므로, 내부 IP 를 넣고 다시 설치합니다.

> **주의**
>
> 연결 토큰은 이 창에서 한 번만 보입니다. 잃어버렸으면 **토큰 재발급** 으로 새로 만듭니다.

실행 환경 행의 메뉴에서 다음을 합니다.

- **기본으로 지정** — 실행 환경을 고르지 않은 AI 가 이 환경에서 돕니다.
- **이름·최대 AI 수 바꾸기** — 최대 AI 수는 지금 실행 중인 AI 수보다 적게 줄일 수 없습니다.
- **토큰 재발급** — 지금 설치된 연결 프로그램은 바로 끊기므로 새 토큰으로 다시 설정합니다. 돌던 AI 는 그대로 돕니다.
- **삭제** — 기본 실행 환경이 아니고, 이 환경을 직접 고른 AI 가 없을 때만 지울 수 있습니다. 막혀 있으면 항목에 이유가 보입니다.

## 에이전트를 삭제한다

상세 맨 아래 **위험 구역** 의 **에이전트 삭제** 를 누르면 확인 창이 뜹니다. 지우는 방식은 에이전트가 남긴 기록에 따라 다릅니다.

- 코멘트·이력 같은 기록이 없으면 에이전트가 지워지고, 담당하던 이슈의 담당자에서도 빠집니다.
- 기록이 있으면 기록은 그대로 두고 이 워크스페이스에서 사용만 중지합니다(「남은 기록이 있어 삭제 대신 사용을 중지했습니다」). 담당하던 이슈의 담당자 칸에는 그대로 남으므로, 필요하면 이슈마다 담당자를 바꿉니다.

공통 비서로 지정된 에이전트를 지우면 지정도 함께 풀립니다. 개인 비서는 여기서 지울 수 없습니다.
