# AI 에이전트 관리

에이전트는 워크스페이스의 AI 구성원입니다. 사람처럼 이슈 담당자가 되고(4장), 대화에서 멘션을 받고, 맡은 일을 합니다. 관리자는 **설정** → **에이전트** 에서 에이전트를 만들고, 실행 방식과 AI 계정을 정하고, 워크스페이스 공통 비서를 지정합니다. 개발을 맡길 AI 는 Works 가 직접 작업 공간을 띄워 돌리게 할 수 있고, 그 작업 공간이 뜰 곳은 같은 화면의 **실행 환경** 탭에서 정하고, 작업 공간 AI 가 쓸 AI 계정은 **계정** 탭에 모아 둡니다.

> **이 장에서 할 수 있는 일**
>
> - 에이전트 목록을 보고 새 에이전트를 만듭니다.
> - 에이전트 상세에서 이름·맡은 일·지시·역할·사용 상태를 바꿉니다.
> - 실행 방식(**기본**·**Claude Code**·**외부**)을 고르고 AI 계정을 연결하거나 고릅니다.
> - AI 가 쓸 계정을 **계정** 탭에 모아 두고 계정마다 5시간·주간 사용률을 봅니다.
> - 공통 비서를 지정하고, 외부 도구로 일할 에이전트에 접속 키를 발급합니다.
> - Claude Code 로 도는 에이전트에 저장소 토큰을 연결하고, 실행을 시작·종료·재시작하고, 작업 설정을 바꿉니다.
> - AI 가 돌 실행 환경을 만들고 관리합니다.

## 화면 도움말을 함께 본다

에이전트 화면의 설명과 주의 사항은 이 장에 모여 있고, 화면에서 바로 **도움말** 패널로 볼 수 있습니다. 화면 위 가운데의 물음표(**도움말 (?)**)를 누르거나, 글을 쓰는 중이 아닐 때 `?` 를 누르면 패널이 열립니다.

패널은 지금 만지는 곳을 따라갑니다. 칸이나 단추를 누르거나 창을 열면 그 칸을 설명하는 절로 바뀝니다. 명령이 든 회색 상자의 **복사** 는 보고 있는 AI 의 아이디와 이 서버의 주소가 채워진 명령을 복사합니다. 패널을 다루는 방법은 [2장](02-login-and-layout.md#도움말을-본다)에 있습니다.

## 에이전트 화면을 연다 {help=agents label=에이전트}

**설정** → **에이전트** 를 열면 위에 탭 셋이 보입니다. 이슈를 맡기거나 대화에서 부를 AI 구성원을 이 화면에서 만들고 관리합니다.

| 탭 | 하는 일 |
| --- | --- |
| **목록** | 에이전트를 보고 새로 만듭니다 — [에이전트 목록을 본다](#agents.list) |
| **실행 환경** | Works 가 AI 작업 공간을 띄울 클러스터를 등록합니다 — [실행 환경을 관리한다](#agents.locations) |
| **계정** | 작업 공간 AI 가 쓸 AI 계정을 모아 둡니다 — [AI 계정을 모아 둔다](#agents.accounts) |

- 공통 비서는 개인 비서를 정하지 않은 구성원 모두가 쓰는 AI 입니다. 공통 비서가 없으면 그 구성원들은 AI 를 쓸 수 없습니다.
- 개인 비서는 구성원이 각자 만든 AI 라 주인이 관리합니다. **개인 비서 표시** 를 켜야 목록에 보입니다.
- 실행 방식은 셋입니다. **기본** 은 Works 가 바로 답하고, **Claude Code** 는 Works 가 작업 공간을 띄우고, **외부** 는 사람이 직접 띄운 도구가 접속 키로 접속합니다.
- AI 구성원의 역할과 사용 여부는 구성원 화면이 아니라 에이전트 상세에서 바꿉니다([에이전트 상세를 연다](#agent)).

### 에이전트 목록을 본다 {help=agents.list label=목록}

**설정** → **에이전트** 의 **목록** 탭에는 에이전트가 한 표에 보입니다. 행마다 이름·**아이디**·**유형**·**실행 방식**·**계정**·**상태**·**실행 환경**·**생성일** 이 보이고, 행을 누르면 그 에이전트의 상세 화면으로 갑니다. 에이전트가 하나도 없거나 공통 비서가 없으면 목록 위에 지금 할 일이 노란 띠로 보입니다.

**유형** 은 셋입니다.

| 유형 | 뜻 |
| --- | --- |
| **공통** | 워크스페이스 공통 비서. 개인 비서가 없는 구성원의 AI 어시스턴트를 맡습니다 |
| **개인** | 구성원 한 사람의 개인 비서. 옆에 주인 이름이 보입니다 |
| **일반** | 이슈 담당 같은 일을 맡기는 에이전트 |

**실행 방식** 열에는 실행 방식이 보입니다. **기본** 은 Works 가 이슈·멘션에 바로 답하는 에이전트, **Claude Code** 는 Works 가 작업 공간을 띄워 돌리는 에이전트, **외부** 는 사람이 직접 띄운 AI 도구가 접속 키로 접속해 일하는 에이전트입니다.

**계정** 열에는 에이전트가 쓰는 AI 계정의 이름이 보입니다. 이름에 마우스를 올리면 이름 전체가, 로그인한 계정이면 그 계정의 이메일도 함께 보입니다. 계정을 고르지 않은 에이전트에는 「—」가 보입니다.

**상태** 열은 실행 방식마다 다릅니다. 외부 에이전트에는 키를 마지막으로 쓴 시각(「마지막 접속 5분 전」 등)이, 기본 에이전트에는 「—」가 보입니다. Claude Code 로 도는 에이전트는 지금 상태와 함께 보이는 것이 한 줄로 나오고, 화면을 새로 고치지 않아도 바뀝니다.

| 상태 | 함께 보이는 것 |
| --- | --- |
| **작업 중** · **차단됨** | 처리 중인 이슈 키(누르면 이슈로 갑니다) |
| **대기 중** | 다음에 할 일을 확인할 시각 |
| **오류** | 실패한 까닭 한 줄 |
| **시작 중** · **종료 중** · **종료됨** | — |

**실행 환경** 열에는 Claude Code 로 도는 에이전트가 도는 실행 환경 이름이 보입니다. 기본 실행 환경이어도 이름이 보이고, 기본·외부 에이전트에는 「—」가 보입니다.

#### 개인 비서를 함께 본다 {help=agents.list.personal label=개인 비서 표시}

**설정** → **에이전트** 의 **목록** 탭 오른쪽 위 **개인 비서 표시** 는 처음에 꺼져 있습니다. 켜면 구성원이 12장에서 만든 개인 비서도 목록에 함께 보입니다. 개인 비서는 구성원이 각자 만든 AI 라 주인이 관리합니다. 관리자는 상세에서 사용 여부를 보거나, AI 계정 연결을 끊고 남은 키를 폐기해 정리만 할 수 있습니다.

#### 새 에이전트를 만든다 {help=agents.list.create label=새 에이전트}

**설정** → **에이전트** 의 **목록** 탭에서 새 AI 구성원을 만듭니다.

1. 머리의 **+ 새 에이전트** 를 누릅니다.
2. **새 에이전트** 창에 **아이디**·**이름**·**이메일** 을 넣습니다. 아이디는 @멘션과 외부 도구의 접속에 쓰입니다.
3. **생성** 을 누릅니다.

만든 에이전트는 실행 방식이 **기본** 입니다. 실행 방식과 AI 계정은 그 에이전트의 상세에서 정합니다([실행을 설정한다](#agent.run)).

### 실행 환경을 관리한다 {help=agents.locations label=실행 환경}

실행 환경은 Works 가 Claude Code AI 의 작업 공간을 띄우는 클러스터입니다. AI 를 Works 가 직접 띄우려면 그 AI 가 돌 클러스터를 **설정** → **에이전트** 의 **실행 환경** 탭에 실행 환경으로 등록합니다. 탭에는 환경마다 이름, **기본** 배지, **연결**(**연결됨**·**끊김**·**설치 대기**), 쓰는 AI, **최대 AI 수**(실행 중인 AI 수와 상한)가 보입니다.

- 실행 환경마다 연결 프로그램을 한 번 설치하면 **연결됨** 으로 바뀝니다. 그다음부터는 에이전트 상세의 **시작**·**종료** 대로 그 클러스터에서 AI 가 돕니다. 추가와 설치는 [실행 환경을 추가한다](#agents.locations.create)와 [연결 프로그램을 설치한다](#agents.locations.install)에 있습니다.
- **최대 AI 수** 는 이 실행 환경에서 동시에 실행할 수 있는 AI 수입니다. 넘으면 AI 시작과 실행 환경 바꾸기가 거절됩니다.
- 새 AI 는 기본 실행 환경을 씁니다. AI 마다 상세 **실행** 의 **작업 설정** 에서 다른 실행 환경을 고를 수 있습니다.
- 이름 바꾸기, 토큰 재발급, 삭제는 행 메뉴에서 합니다([실행 환경을 고치거나 지운다](#agents.locations.menu)).

> **참고**
>
> AI 작업 공간의 작업 폴더는 AI 가 처음 뜬 클러스터 노드의 디스크(기본 `/var/lib/genia-agents`)에 생깁니다. AI 는 그 노드에 고정돼 다시 시작해도 같은 폴더를 이어 씁니다. 그 노드를 쓸 수 없게 되어 AI 가 켜지지 않으면 AI 를 **종료** 했다가 다시 **시작** 합니다 — 다른 노드에서 새 작업 폴더로 뜹니다. AI 를 종료해도 노드의 작업 폴더는 지워지지 않습니다.

#### 실행 환경을 추가한다 {help=agents.locations.create label=실행 환경 추가}

**설정** → **에이전트** 의 **실행 환경** 탭에서 새 클러스터를 등록합니다.

1. 머리의 **+ 실행 환경 추가** 를 누릅니다.
2. **이름**·**설명 (선택)**·**최대 AI 수** 를 넣습니다. 최대 AI 수는 이 실행 환경에서 동시에 띄울 수 있는 AI 수입니다.
3. **추가하고 토큰 발급** 을 누르면 연결 토큰과 설치 순서가 보입니다. 토큰을 복사해 파일로 저장합니다.
4. 클러스터 담당자가 안내된 순서대로 연결 프로그램을 설치합니다. 설치가 끝나면 1분쯤 뒤 **연결됨** 으로 바뀝니다.

설치 순서와 설치가 끝나지 않을 때 할 일은 [연결 프로그램을 설치한다](#agents.locations.install)에 있습니다.

#### 연결 프로그램을 설치한다 {help=agents.locations.install label=연결 토큰}

실행 환경을 추가하거나 **토큰 재발급** 을 하면 「<이름> 연결 토큰」 창에 연결 토큰과 설치 순서가 보입니다. 클러스터 담당자는 이 순서대로 클러스터에 연결 프로그램을 설치합니다. 설치가 끝나면 1분쯤 뒤 **실행 환경** 탭의 **연결** 이 **연결됨** 으로 바뀝니다.

사내 클러스터처럼 Works 주소에 공인 주소로 닿지 못하고 내부 IP 로 가야 하는 곳이면, 설치 순서 위의 **Works 에 내부 IP 로 접속하는 경우 (선택)** 칸에 그 IP 를 넣습니다. 설치 명령에 Works 주소를 그 IP 로 푸는 값이 더해지고, 연결 프로그램과 그 프로그램이 띄우는 AI 작업 공간 모두에 들어갑니다. 칸을 비우면 명령은 그대로입니다.

**설치 대기** 가 오래 가면 클러스터에서 Works 주소에 닿지 못하는 경우가 많습니다. 설치 순서 아래의 **연결이 안 될 때 연결 프로그램 기록 보기** 명령으로 기록을 봅니다. fetch failed 가 거듭 보이면 내부 IP 칸을 채워 다시 설치합니다.

> **주의**
>
> 연결 토큰은 이 창에서 한 번만 보입니다. 잃어버렸으면 실행 환경 행 메뉴의 **토큰 재발급** 으로 새로 만듭니다.

#### 실행 환경을 고치거나 지운다 {help=agents.locations.menu label=실행 환경 메뉴}

**설정** → **에이전트** 의 **실행 환경** 탭에서 행 끝의 메뉴를 누르면 다음 항목이 보입니다.

- **기본으로 지정** — 실행 환경을 고르지 않은 AI 가 이 환경에서 돕니다.
- **이름·최대 AI 수 바꾸기** — 최대 AI 수는 지금 실행 중인 AI 수보다 적게 줄일 수 없습니다.
- **토큰 재발급** — 새 연결 토큰을 만듭니다. 돌던 AI 는 그대로 돕니다.
- **삭제** — 기본 실행 환경이 아니고, 이 환경을 쓰도록 설정된 AI 가 없을 때만 지울 수 있습니다. 막혀 있으면 항목에 이유가 보입니다.

> **주의**
>
> 토큰을 재발급하면 옛 토큰은 바로 끊깁니다. 클러스터의 연결 프로그램이 새 토큰을 쓰도록 바꾸기 전까지 그 실행 환경의 AI 를 관리할 수 없습니다.

### AI 계정을 모아 둔다 {help=agents.accounts label=계정}

**설정** → **에이전트** 의 **계정** 탭에는 작업 공간 AI 가 일할 때 쓰는 계정이 한 표에 모여 있고, 계정마다 사용률이 보입니다. 목록은 1분마다 새로 받고, 남은 시간과 「N분 전」은 화면을 열어 둔 동안 1분마다 저절로 바뀝니다.

| 칸 | 보이는 것 |
| --- | --- |
| **계정** | 라벨. 로그인 계정의 이메일은 수정 창에서 봅니다 |
| **유형** | 종류(**Claude 구독**·**OpenAI 호환**·**ChatGPT 로그인**·**Gen:iA 로그인**) |
| **5시간** | 5시간 창의 사용률과 막대, 초기화까지 남은 시간(「2시간 25분 뒤 초기화」) |
| **주간** | 주간 창의 사용률과 막대, 초기화 날짜와 시각(「11/12 (목) 오후 2:05 초기화」) |
| **쓰는 AI** | 이 계정을 고른 AI 이름(누르면 그 AI 상세로 갑니다), 그 아래 AI 가 마지막으로 일한 때(「마지막 사용 2분 전」). 고른 AI 가 없으면 「없음」(이때는 마지막 사용도 보이지 않습니다) |
| **상태** | 아래 표 |
| **사용량 확인** | 사용률을 마지막으로 잰 때(「5분 전」). 아직 재지 않았으면 「—」 |

5시간·주간 사용률은 Works 가 10분마다 잽니다. 막대는 75% 를 넘으면 주황, 100% 에 닿으면 빨강으로 바뀝니다. 사용률을 아직 재지 못했으면(재기 전·확인 실패·확인 필요) 「—」가, 재었는데 그 창의 값이 오지 않았으면 「값 없음」이 보입니다. 마지막으로 잰 뒤 초기화 시각이 지난 창은 사용률이 흐리게 보이고, 남은 시간·날짜 대신 「초기화됨 · 다음 확인 때 갱신」이 보입니다. 다음에 사용률을 잴 때 새 값으로 바뀝니다.

**OpenAI 호환** 과 **Gen:iA 로그인** 계정은 한도를 재지 않습니다. 5시간·주간 두 칸을 합쳐 **한도 없음** 이 한 번 보이고, **사용량 확인** 칸은 「—」입니다. AI 가 마지막으로 일한 때는 다른 계정처럼 **쓰는 AI** 칸에 보입니다.

| 상태 | 뜻 |
| --- | --- |
| **다시 로그인 필요** | 로그인이 풀렸습니다. 계정을 수정해 로그인 정보를 새로 넣습니다 |
| **확인 필요** | 예전 연결에서 옮겨 온 로그인 계정이라 아직 확인하지 않았습니다 |
| **확인 실패** | 사용률을 재지 못했습니다 |
| **한도 도달** | 5시간이나 주간 한도를 다 썼습니다. 초기화될 때까지 이 계정의 AI 는 일하지 못합니다 |
| **곧 한도** | 사용률이 75% 를 넘었습니다 |
| **정상** | 한도에 여유가 있거나, 한도를 재지 않는 계정입니다 |
| **확인 전** | 아직 사용률을 재지 않았습니다 |

마지막으로 사용률을 재다 실패했으면 **확인 실패** 아래에 까닭이 한 줄(「연결 실패」) 보입니다. **확인 필요** 계정도 마지막으로 재다 실패했으면 「사용량 확인 실패 · 연결 실패」처럼 까닭이 함께 보입니다.

한 계정을 여러 AI 가 같이 쓰면 사용률도 함께 오릅니다. 한도에 자주 닿으면 AI 들이 나눠 쓰도록 계정을 더 넣습니다([계정을 추가한다](#agents.accounts.add)).

#### 계정을 추가한다 {help=agents.accounts.add label=계정 추가}

**설정** → **에이전트** 의 **계정** 탭에서 작업 공간 AI 가 쓸 계정을 넣습니다.

1. 머리의 **+ 계정 추가** 를 누릅니다.
2. **종류** 를 고릅니다.
3. **라벨** 에 알아보기 쉬운 이름을 적습니다. 비우면 「Claude 구독 계정」처럼 종류 이름이 붙습니다.
4. 종류에 맞는 값을 넣습니다. Claude 구독은 토큰(워크스페이스를 지정하지 않고 만든 Anthropic API 키라면 **Anthropic 워크스페이스 ID(선택)** 도), OpenAI 호환은 주소와 API 키(**연결 확인** 으로 미리 확인할 수 있습니다), ChatGPT·Gen:iA 로그인은 로그인 정보 파일(auth.json)입니다.
5. **추가** 를 누릅니다. 같은 키의 계정이 이미 있으면 추가되지 않고 그 계정을 쓰라고 알려 줍니다.

> **주의**
>
> ChatGPT·Gen:iA 로그인 계정에는 내 컴퓨터에서 쓰던 로그인 파일을 그대로 넣지 않습니다. 이 계정용으로 새로 로그인한 파일을 넣어야 합니다. 같은 로그인을 두 곳에서 쓰면 한쪽이 로그아웃됩니다.

#### 계정을 고치거나 지운다 {help=agents.accounts.menu label=계정 메뉴}

**설정** → **에이전트** 의 **계정** 탭에서 줄 끝의 ⋯ 메뉴를 누르면 다음 항목이 보입니다.

- **수정** — 라벨을 바꾸거나 **키 교체** 를 눌러 키·로그인 정보를 새로 넣습니다. 지금 키는 다시 보이지 않고, 종류는 바꿀 수 없습니다. **키 교체** 를 열었으면 키를 다 넣거나 **교체 안 함** 을 눌러야 저장할 수 있습니다. OpenAI 호환 계정은 지금 주소도 다시 보이지 않아서, 키를 바꾸려면 프리셋과 주소를 다시 고르고 넣어야 저장할 수 있습니다. 키를 바꾸면 이 계정을 쓰는 AI 의 작업 공간이 새 키로 다시 시작됩니다.
- **삭제** — 확인 창에서 한 번 더 누르면 지워집니다. 이 계정을 쓰는 AI 가 있으면 지워지지 않으니, 그 AI 들의 상세에서 먼저 다른 계정으로 바꿉니다.

## 에이전트 상세를 연다 {help=agent label=에이전트 상세}

**설정** → **에이전트** 의 목록에서 행을 누르면 에이전트 상세 화면이 열립니다. 이 AI 를 쓸 수 있게 할지, 무엇을 맡기고 어떻게 돌릴지 이 화면에서 정합니다. 머리 왼쪽의 뒤로 가기 단추를 누르면 목록으로 돌아갑니다. 상세는 위에서부터 다음 섹션으로 나뉩니다.

| 섹션 | 하는 일 |
| --- | --- |
| **상태** | 사용 여부와 지금 하는 일, 시작·종료 — [사용 상태를 본다](#agent.status) |
| **기본 정보** | 아바타·**이름**·**아이디** — [기본 정보를 바꾼다](#agent.profile) |
| **역할 할당** | 이 AI 에게 줄 역할 — [역할을 준다](#agent.roles) |
| **맡은 일과 지시** | 다른 AI 가 읽는 설명과 이 AI 가 따르는 규칙 — [맡은 일과 지시를 적는다](#agent.work) |
| **실행** | 실행 방식, AI 계정, 공통 비서, 저장소 연결, 작업 설정, 접속 키 — [실행을 설정한다](#agent.run) |
| **코드 저장소** | 이 AI 가 맡는 프로젝트 — [맡는 프로젝트를 확인한다](#agent.repos) |
| **위험 구역** | 에이전트 삭제 — [에이전트를 삭제한다](#agent.danger) |

개인 비서는 주인이 관리하므로 이름·맡은 일·지시를 바꿀 수 없고, **역할 할당** 과 **위험 구역** 이 없습니다. 공통 비서로 지정된 AI 는 지정을 먼저 풀어야 사용 중지나 실행 방식 바꾸기를 할 수 있습니다.

### 사용 상태를 본다 {help=agent.status label=상태}

에이전트 상세 맨 위 **상태** 섹션에서 이 AI 를 쓸지(**사용** 스위치)와 지금 하는 일을 봅니다. 보이는 것은 실행 방식마다 다릅니다.

- **Claude Code** 로 도는 AI 는 **실행** 묶음에 상태·처리 중인 이슈·실행 시간·CPU·메모리와 **시작**·**종료**·**재시작** 이 보입니다([실행을 시작하고 멈춘다](#agent.status.run)).
- **외부** 방식 AI 는 마지막으로 접속한 시각(「마지막 접속 5분 전」 등)이 보이고, 아직 접속한 적이 없으면 「아직 접속 안 함」이 보입니다.
- 사용을 멈추는 방법은 [에이전트 사용을 멈춘다](#agent.status.use)에 있습니다.

#### 에이전트 사용을 멈춘다 {help=agent.status.use label=사용}

에이전트 상세 **상태** 의 **사용** 스위치를 끄면 확인 창이 뜨고, 확인하면 그 AI 는 이 워크스페이스에 접속하거나 일할 수 없습니다. 실행 중이던 AI 는 실행도 멈춥니다. 다시 켜도 실행은 직접 시작해야 합니다.

공통 비서로 지정된 AI 는 지정을 먼저 풀어야 사용을 멈출 수 있습니다. 개인 비서의 스위치는 주인이 관리하므로 여기서 바꿀 수 없습니다.

#### 실행을 시작하고 멈춘다 {help=agent.status.run label=실행}

**Claude Code** 로 도는 AI 의 상세에서 **상태** 의 **실행** 묶음으로 작업 공간을 시작하고 멈춥니다.

1. 확인 항목(「Claude 구독 연결」 같은 AI 계정 연결·**저장소 연결**·맡는 프로젝트·**실행 환경 여유**)이 모두 **통과** 인지 봅니다. 연결이 빠진 저장소 호스트가 있거나 맡는 프로젝트가 하나도 없으면 실행을 시작할 수 없습니다.
2. **시작** 을 누릅니다. 작업 설정을 고친 채라면 **저장하고 시작** 이 보입니다. **시작 중** 을 거쳐 **대기 중** 이나 **작업 중** 으로 바뀝니다.

실행 중에는 상태와 처리 중인 이슈, 실행 시간, CPU·메모리 사용량, 실행 환경이 보입니다.

- 실행 환경 클러스터에 사용량을 재는 metrics-server 가 없으면 CPU·메모리가 「알 수 없음」으로 보이고 그 아래에 이유가 한 줄 나옵니다. **실행 환경** 탭에도 그 환경의 연결 배지 옆에 「사용량 측정 안 됨」이 보입니다. 사용량을 보려면 실행 환경을 추가할 때의 설치 순서 마지막 단계(선택)로 metrics-server 를 설치합니다.
- **재시작** 은 작업 공간을 새로 띄웁니다. 실패하면 **오류** 와 함께 까닭이 한 줄 보이고 **재시작** 이 나옵니다.
- 작업 설정이나 AI 계정을 바꾸면 「바꾼 설정은 쉴 때 적용돼요.」가 보입니다. 쉴 때는 하던 이슈를 마치고 다음 일을 기다릴 때입니다. **지금 적용** 을 누르면 작업 공간을 새 설정으로 다시 띄우고, 다시 뜬 작업 공간이 하던 이슈를 이어 받습니다. 일하는 중이면 확인 창이 뜹니다.
- **종료** 는 하던 일을 멈추고 작업 공간을 끕니다. 일하는 중인 AI 에서 누르면 「<AI 이름> 을 종료할까요?」 확인 창에 끊기는 이슈 키와, 커밋·push 하지 않은 변경이 지워진다는 안내가 보입니다. 그래도 끝내려면 **종료** 를, 그만두려면 **취소** 를 누릅니다.

> **주의**
>
> **종료** 하면 작업 공간이 지워져 커밋·push 하지 않은 변경은 되살릴 수 없습니다. 하던 일이 있으면 **새 작업 받기** 를 끄고([새 작업을 그만 받게 한다](#agent.status.new-work)) **대기 중** 이 된 것을 본 뒤 종료합니다.

#### 새 작업을 그만 받게 한다 {help=agent.status.new-work label=새 작업 받기}

Claude Code 로 도는 AI 를 곧 종료하거나 쉬게 하고 싶은데 하던 일은 끊기면 안 될 때 씁니다. 에이전트 상세 **상태** 의 **실행** 묶음에 있는 **새 작업 받기** 스위치를 끕니다. 이름 아래에 「끄면 하던 작업은 마치고, 새 이슈는 가져가지 않아요.」가 보입니다. AI 가 종료된 상태에서는 스위치가 보이지 않습니다.

끄면 AI 는 하던 일(리뷰 수정, 최신 main 반영, 질문 답하기, PR 리뷰)은 계속 마치지만, 대기열의 이슈를 가져가지 않고 새로 맡은 이슈의 구현도 시작하지 않습니다. 알약 옆과 에이전트 목록의 **상태** 칸에 **새 작업 안 받음** 배지가 보입니다. 하던 일을 다 마치면 AI 는 **대기 중** 으로 남습니다. 스위치를 바꿔도 작업 공간은 다시 뜨지 않습니다.

스위치 값은 **재시작** 해도 그대로입니다. **종료** 하면 켜진 상태로 돌아갑니다.

#### AI 의 작업 화면을 본다 {help=agent.status.screen label=작업 화면 보기}

Claude Code 로 도는 AI 의 작업 공간이 떠 있으면 에이전트 상세 **상태** 에 **작업 화면 보기** 가 나옵니다. 누르면 AI 가 일하는 터미널 화면이 창으로 열립니다.

1. **작업 화면 보기** 를 누릅니다. 머리에 「연결됨 · 보기 전용」이 보이고, AI 가 일하는 화면이 그대로 나옵니다.
2. 화면이 여러 개면 머리의 탭(맡은 프로젝트 키, **알림** 등)을 눌러 바꿔 봅니다. 탭을 바꿔도 AI 가 보는 화면은 바뀌지 않습니다.
3. 다 봤으면 창을 닫습니다. 연결이 끊기면 까닭이 보이고 **다시 연결** 이 나옵니다.

실행 환경이 입력을 허용하면 머리에 **입력 허용** 이 보입니다. 누르면 확인 창이 뜨고, 확인하면 치는 키가 AI 화면에 그대로 갑니다. 그동안 창 위에 「입력 중」 띠가 보이고, **보기 전용으로** 를 누르면 다시 보기만 합니다.

> **주의**
>
> 입력은 AI 작업 공간에서 명령을 직접 실행하는 것과 같습니다. AI 가 하던 일이 바뀌거나 AI 의 비밀값에 닿을 수 있고, 입력한 내용은 감사 기록에 남습니다. 그래서 입력은 실행 환경을 설치할 때 따로 켜야만 쓸 수 있고, 기본은 꺼져 있습니다.

### 기본 정보를 바꾼다 {help=agent.profile label=기본 정보}

에이전트 상세 **기본 정보** 에서 **이름** 과 **아이디** 를 고치고 **저장** 을 누릅니다. 이름과 아바타는 목록·담당자 고르기·채팅에 이 AI 의 모습으로 보입니다. 아이디는 @멘션과 외부 도구의 접속에 쓰이므로, 바꾸면 예전 아이디로 한 멘션은 이 AI 에게 가지 않습니다.

개인 비서는 구성원이 만든 AI 라 이름·아바타·맡은 일·지시를 주인이 정합니다.

### 역할을 준다 {help=agent.roles label=역할 할당}

에이전트 상세 **역할 할당** 에서 이 AI 에게 줄 역할을 고르고 저장합니다. AI 에게는 관리자 역할이나 관리 권한이 든 역할을 줄 수 없습니다. 이미 가진 그런 역할은 화면에 남아 있어 뺄 수 있습니다.

### 맡은 일과 지시를 적는다 {help=agent.work label=맡은 일과 지시}

에이전트 상세 **맡은 일과 지시** 에 이 AI 가 무엇을 맡는지와 일할 때 따를 규칙을 적습니다.

1. **맡은 일** 에 이 AI 가 무엇을 맡고 어떻게 일하는지 적습니다. 다른 AI 가 일을 맡길 상대를 고를 때 이 설명을 읽습니다.
2. **지시** 에 이 AI 가 이슈를 맡을 때마다 따를 규칙을 적습니다.
3. **저장** 을 누릅니다.

지시는 실행 방식과 상관없이 따르고, 저장하면 다음 이슈부터 따릅니다. 다른 AI 는 이 지시를 보지 않습니다. 프로젝트 저장소의 규칙과 부딪히면 저장소 규칙이 먼저입니다.

### 실행을 설정한다 {help=agent.run label=실행}

에이전트 상세 **실행** 섹션에서 이 AI 를 어떻게 돌릴지 정합니다. 맨 위에서 실행 방식을 고르고([실행 방식을 고른다](#agent.run.mode)), 그 아래에는 방식마다 다른 묶음이 보입니다.

| 실행 방식 | 보이는 묶음 |
| --- | --- |
| **기본** | **AI 계정**([AI 계정을 연결한다](#agent.run.account)) · **공통 비서**([공통 비서를 지정한다](#agent.run.assistant)) · **접속 키** |
| **Claude Code** | **AI 계정**([Claude Code 의 계정을 고른다](#agent.run.account.pick)) · **저장소 연결**([저장소를 연결한다](#agent.run.repo)) · **작업 설정**([작업 설정을 바꾼다](#agent.run.settings)) · **접속 키** |
| **외부** | **접속 키**([접속 키를 관리한다](#agent.run.keys), [외부 도구에 연결한다](#agent.run.keys.connect)) |

개인 비서는 기본 방식으로만 돕니다. 관리자는 AI 계정 연결을 끊거나 남은 키를 폐기해 정리만 할 수 있습니다.

#### 실행 방식을 고른다 {help=agent.run.mode label=실행 방식}

에이전트 상세 **실행** 섹션 맨 위의 **실행 방식** 카드 셋 가운데 하나를 고릅니다.

| 카드 | 뜻 |
| --- | --- |
| **기본** | Works 가 실행하고, 이슈·멘션에 바로 답합니다. AI 계정을 연결해야 일합니다 |
| **Claude Code** | Works 가 실행 환경에 이 AI 의 작업 공간을 띄워, 맡은 이슈를 개발·테스트하고 PR 까지 올립니다 |
| **외부** | 사람이 직접 띄운 AI 도구가 이 AI 의 접속 키로 접속해 일합니다 |

1. 바꿀 카드를 누릅니다. 카드를 누르기만 해서는 바뀌지 않고, 그 방식에 필요한 칸이 아래에 펼쳐집니다.
2. **Claude Code** 면 펼쳐진 작업 설정(모델·대기열 라벨·실행 환경)을 채웁니다.
3. **바꾸기** 를 누릅니다. 확인 창에 바꾸면 무엇이 달라지는지(지워지는 설정, 폐기되는 키 등)가 보입니다.
4. 확인 창의 **바꾸기** 를 누르면 저장됩니다.

실행 중인 AI 는 먼저 **종료** 해야 방식을 바꿀 수 있습니다. 공통 비서와 개인 비서는 서버에서 대화해야 하므로 **기본** 으로만 돕니다. 공통 비서를 다른 방식으로 바꾸려면 공통 비서 지정을 먼저 풉니다. **Claude Code** 를 다른 방식으로 바꾸면 그 AI 는 고른 계정에서 풀립니다.

#### AI 계정을 연결한다 {help=agent.run.account label=AI 계정}

**기본** 방식 에이전트는 상세 **실행** 섹션의 **AI 계정** 에 이 AI 만 쓰는 연결을 넣습니다. 연결해야 이 AI 가 답할 수 있습니다. 연결 방식(예: Claude 구독), 등록일, 최근 사용 시각이 보이고, 아직 연결하지 않았으면 **연결하기** 를 누릅니다. 연결 방식은 Claude 구독 토큰 또는 OpenAI 호환 API 키입니다.

- Claude 구독으로 연결할 때 **토큰** 아래의 **Anthropic 워크스페이스 ID(선택)** 는 워크스페이스를 지정하지 않고 만든 Anthropic API 키를 넣을 때만 적습니다. ID 는 Anthropic 콘솔의 Workspaces 에서 확인합니다. 그런 키를 ID 없이 넣으면 연결되지 않고 이 칸 아래에 안내가 보입니다.
- **다시 연결** 은 토큰을 새로 넣고, **연결 끊기** 는 저장한 토큰·키를 폐기합니다. 연결을 끊으면 에이전트가 AI 를 부를 수 없게 됩니다.
- 등록한 토큰·키 값은 다시 보이지 않습니다. 화면에는 연결 종류와 날짜만 보입니다.

**Claude Code** 처럼 작업 공간에서 도는 AI 는 AI 마다 연결을 넣지 않고 **계정** 탭의 계정을 고릅니다([Claude Code 의 계정을 고른다](#agent.run.account.pick)). **외부** 방식은 사람이 띄운 AI 도구가 자기 계정으로 일하므로 여기서 정할 AI 계정이 없습니다. 개인 비서의 AI 계정은 주인이 자기 설정에서 정합니다(12장).

##### Claude Code 의 계정을 고른다 {help=agent.run.account.pick label=계정 고르기}

**Claude Code** 로 도는 AI 는 AI 마다 연결을 넣지 않고, **설정** → **에이전트** 의 **계정** 탭에 넣어 둔 계정 가운데 하나를 상세 **실행** 의 **AI 계정** 에서 고릅니다. 여러 AI 가 한 계정을 함께 쓸 수 있습니다. 맞는 종류의 계정이 없으면 계정 탭에 먼저 추가합니다([계정을 추가한다](#agents.accounts.add)).

1. **AI 계정** 에 지금 고른 계정의 라벨·종류·상태와 **5시간**·**주간** 사용률이 보입니다. 아직 고르지 않았으면 「아직 고른 계정이 없습니다」가 보입니다. 예전 방식으로 이 AI 에 직접 넣어 둔 키가 남아 있으면 그 대신 「예전 방식으로 연결된 Claude 구독 키가 있어요 — 계정을 고르면 그 계정으로 바뀝니다」처럼 보이고, 계정을 고르기 전까지 AI 는 그 키로 일합니다.
2. **계정 고르기**(이미 골랐으면 **바꾸기**)를 누릅니다.
3. 창에는 이 실행 방식이 쓰는 종류의 계정만 보입니다(예: Claude Code 는 Claude 구독 계정). 줄마다 5시간·주간 사용률(한도를 재지 않는 계정은 **한도 없음**), 상태, 이 계정을 쓰는 다른 AI 수가 보이니 여유 있는 계정을 고릅니다.
4. **이 계정으로 바꾸기** 를 누릅니다. AI 가 꺼져 있거나 쉬는 중이면 작업 공간이 새 계정으로 바로 다시 시작합니다.

맞는 종류의 계정이 없으면 창에 안내와 **계정 탭에서 먼저 추가** 링크가 보입니다. 링크를 눌러 계정을 넣은 뒤 다시 고릅니다.

> **참고**
>
> AI 가 실행 중인데 쉬는 중이 아닐 때(일하는 중이거나 상태를 아직 모를 때) 계정을 바꾸면 하던 일을 끊지 않습니다. 하던 이슈를 마칠 때까지 지금 계정으로 일하고, 쉴 때 새 계정으로 다시 시작합니다. 그래서 실행 중인 AI 의 **AI 계정** 옆에는 「실행 중이면 쉴 때 적용」이 보이고, 고르는 창에도 「하던 작업이 있으면 마치고 쉴 때 새 계정으로 바뀌어요」가 보입니다. 바로 바꾸려면 **상태** 의 **지금 적용** 을 누릅니다. 계정 탭에서 그 계정의 키를 바꾸면 기다리지 않고 바로 새 키로 다시 시작합니다.

#### 공통 비서를 지정한다 {help=agent.run.assistant label=공통 비서}

**기본** 방식 에이전트의 상세 **실행** 섹션에는 **공통 비서** 묶음이 있습니다. 공통 비서는 개인 비서를 정하지 않은 구성원 모두가 쓰는 AI 로, 그 구성원들의 **AI 어시스턴트** 와 홈 AI 비서를 맡습니다.

스위치를 켜면 이 에이전트가 워크스페이스 공통 비서가 됩니다. 먼저 AI 계정을 연결해야 지정할 수 있고, 개인 비서는 공통 비서로 지정할 수 없습니다. 지정할 때 저장된 AI 계정으로 모델을 먼저 확인하고, 확인하지 못하면 한 번 더 묻고 지정합니다.

지정하면 그 아래에서 **모델** 과 **생각의 깊이**, **추천 질문 모델** 을 고릅니다. 생각의 깊이는 **설정 안 함**(모델 기본값)과 고른 모델이 받는 단계(**낮게**·**보통**·**높게**·**매우 높게**·**최대** 중 일부) 가운데서 고릅니다. 모델마다 받는 단계가 달라, 지금 단계를 받지 않는 모델로 바꾸면 그 모델이 받는 바로 아래 단계로 맞춰집니다. 단계를 알 수 없는 OpenAI 호환 모델은 **설정 안 함** 만 보입니다. 추천 질문 모델은 추천·후속 질문을 만들 때만 쓰는 가벼운 모델입니다.

공통 비서 지정을 해제하면 개인 비서가 없는 구성원은 화면 위 **AI 어시스턴트** 단추와 AI 기능을 쓸 수 없게 됩니다. 이미 열려 있는 화면은 새로 고친 뒤에 바뀔 수 있습니다.

#### 저장소를 연결한다 {help=agent.run.repo label=저장소 연결}

**Claude Code** 로 도는 AI 는 맡은 프로젝트의 저장소에서 코드를 받고 PR(GitLab 은 MR)을 올릴 때 저장소 호스트(예: github.com)의 토큰을 씁니다. GitHub 와 GitLab 저장소를 모두 다룹니다. 토큰은 AI 마다, 호스트마다 따로 저장하고, 저장한 뒤에는 다시 보이지 않습니다. 에이전트 상세 **실행** 섹션의 **저장소 연결** 에는 맡는 프로젝트 저장소의 호스트가 한 줄씩 보입니다. 연결된 호스트에는 등록일과 최근 사용 시각이 보이고, 아직 연결하지 않은 호스트에는 **연결 안 됨** 이 보입니다. 연결이 빠진 호스트가 있으면 실행을 시작할 수 없습니다.

1. **저장소 연결** 에서 **연결 안 됨** 인 호스트 줄의 **연결하기** 를 누릅니다.
2. 저장소에서 토큰을 만들어 **토큰** 칸에 붙여 넣습니다. 토큰 만드는 법은 [저장소 토큰을 만든다](#agent.run.repo.token)에 있습니다.
3. **연결하기** 를 누릅니다.

이미 연결한 호스트의 토큰을 바꾸려면 **다시 연결** 을, 더는 쓰지 않으려면 **연결 끊기** 를 누르고 확인 창에서 한 번 더 누릅니다. 맡는 프로젝트에 없는 호스트를 미리 연결하려면 **+ 다른 호스트 추가** 를 누릅니다. 실행 중에 연결을 바꾸거나 끊으면 다음에 다시 시작할 때부터 적용됩니다.

##### 저장소 토큰을 만든다 {help=agent.run.repo.token label=토큰}

에이전트 상세 **저장소 연결** 의 **연결하기**·**다시 연결**·**+ 다른 호스트 추가** 창에는 **저장소 종류**·**호스트**·**토큰** 칸이 있습니다. **저장소 종류** 가 맞는지 확인하고, 그 저장소 호스트에서 만든 토큰을 **토큰** 칸에 붙여 넣습니다.

- GitHub 토큰은 GitHub › Settings › Developer settings › Fine-grained personal access tokens 에서 만듭니다. 대상 저장소를 고르고 Contents 와 Pull requests 를 Read and write 로 줍니다.
- GitLab 토큰은 GitLab › Preferences › Access tokens 에서 만드는 Personal access token 입니다. api 와 write_repository 범위를 고릅니다.
- 호스트 줄에서 연 창은 호스트 이름을 고칠 수 없습니다. **+ 다른 호스트 추가** 에서 연 창은 **호스트** 에 `github.com` 처럼 이름만 적고 `https://` 나 경로는 붙이지 않습니다.
- 입력한 토큰은 저장하면 다시 보이지 않습니다. 다시 연결하면 이전 토큰은 자동으로 해제됩니다.

#### 작업 설정을 바꾼다 {help=agent.run.settings label=작업 설정}

**Claude Code** 로 도는 AI 의 상세 **실행** 섹션 **작업 설정** 에서 모델·대기열 라벨·실행 환경을 바꾸고 저장합니다.

- 모델 선택지에는 연결한 AI 계정이 쓸 수 있는 모델이 보입니다. 목록 맨 앞의 Opus(최신)·Sonnet(최신)도 고를 수 있고, 계정의 모델 목록을 받지 못하면 이 둘만 보입니다. Opus(최신)·Sonnet(최신)은 늘 그 계열의 가장 새 모델을 씁니다.
- 대기열 라벨을 적으면 맡긴 이슈 말고도 그 라벨이 붙은 담당자 없는 이슈를 가져가 처리합니다.
- 실행 환경을 바꾸면 쉴 때를 기다리지 않고 바로 옮겨 갑니다.
- 작업 공간이 쓰는 CPU·메모리는 실행 방식마다 정해져 있습니다.

실행 중에 모델이나 대기열 라벨을 바꾸면 **상태** 에 「바꾼 설정은 쉴 때 적용돼요.」가 보입니다. 하던 일을 끊고 바로 바꾸려면 **지금 적용** 을 누릅니다([실행을 시작하고 멈춘다](#agent.status.run)).

#### 접속 키를 관리한다 {help=agent.run.keys label=접속 키}

에이전트 상세 **실행** 섹션의 **접속 키** 에는 이 AI 로 Works 에 접속하는 키가 보입니다. 키를 다루는 방법은 실행 방식마다 다릅니다.

- **외부** 방식은 사람이 띄운 AI 도구가 이 키로 접속합니다. 키 이름을 넣고 **키 발급** 을 누르면 **새 API 키** 창에 새 키가 한 번만 보이므로 복사해 둡니다. 도구에 키를 넣는 순서는 [외부 도구에 연결한다](#agent.run.keys.connect)에 있습니다. 키를 아직 한 번도 쓰지 않았으면 **접속 키** 아래의 **연결 방법** 을 눌러 도움말 패널에서 그 절을 바로 엽니다.
- 발급한 키는 목록에서 폐기할 수 있습니다. 폐기한 키로는 바로 접속할 수 없습니다. 키를 잃어버렸으면 폐기하고 새로 발급합니다.
- **Claude Code** 로 도는 AI 의 키는 Works 가 만들고 주기적으로 바꾸므로 직접 발급할 필요가 없습니다. **접속 키** 에 다음 교체 무렵이 보입니다. 예전에 직접 발급한 키가 남아 있으면 이제 쓰지 않으니 폐기합니다.

Works 가 만드는 키는 30일짜리이고, 만료 7일 전부터 새 키로 바뀝니다. 새 키는 쉴 때 적용되고, 옛 키가 하루 안에 만료되면 일하는 중이어도 바로 바뀝니다.

##### 외부 도구에 연결한다 {help=agent.run.keys.connect label=외부 도구 연결}

**외부** 방식 에이전트는 사람이 띄운 Claude Code 가 genia-works 플러그인으로 이 AI 가 되어 일합니다. 그 컴퓨터의 Claude Code 에서 다음 순서로 연결합니다.

1. 에이전트 상세 **실행** 의 **접속 키** 에서 키를 발급합니다. 키는 발급할 때 한 번만 보입니다.
2. genia-works 플러그인을 설치합니다. 컴퓨터마다 한 번만 하고, 이미 설치했으면 건너뜁니다.

   ```
   /plugin marketplace add {app.origin}/claude/marketplace.json
   /plugin install genia-works@genia-works
   ```

3. 서버 주소를 확인합니다. 기본 주소 서버라면 설정을 그대로 둡니다.
   {if app.customMcpServer}
   이 서버는 기본 주소가 아니므로 플러그인 설정을 엽니다.

   ```
   /plugin configure genia-works@genia-works
   ```

   설정의 서버 주소를 다음 주소로 바꿉니다.

   ```
   {app.mcpEndpoint}
   ```
   {/if}
4. 이 AI 로 로그인합니다. 다음 명령에서 「새 AI 추가」를 고르고 1에서 발급한 키를 붙여 넣습니다. 이름은 이 AI 의 아이디 `{agent.username}` 으로 넣습니다.

   ```
   /genia-works:login
   ```

   그다음 지금 세션을 이 AI 로 바꾸려면 첫 명령을, 처음부터 이 AI 로 띄우려면 둘째 명령을 씁니다.

   ```
   /genia-works:as {agent.username}
   ```

   ```
   GENIA_WORKS_AS={agent.username} claude
   ```

5. 자동으로 이슈를 처리하게 합니다. 이 AI 전용 터미널에서 첫 명령으로 띄우고, 뜬 Claude Code 안에서 둘째 명령으로 시작합니다.

   ```
   GENIA_WORKS_AS={agent.username} GENIA_WORKS_UNATTENDED=1 claude --permission-mode bypassPermissions
   ```

   ```
   /loop /genia-works:work-loop <프로젝트 키>
   ```

이 AI 로 바꾼 세션만 이 AI 로 일하고, 다른 세션은 내 계정 그대로입니다. `/genia-works:logout` 하면 내 계정으로 돌아옵니다.

자동으로 이슈 처리를 띄우면 할당된 이슈를 하나씩 가져와 구현·검증한 뒤 이슈 브랜치를 push 해 GitHub PR 을 만들고, 검토자가 머지하면 검토 대기로 올립니다. main 에 직접 push 하거나 배포하지는 않습니다. PR 을 만들려면 이 AI 가 도는 컴퓨터에 gh 와 GitHub 토큰(GH_TOKEN)이 있어야 합니다. 없으면 그 이슈를 「인증 필요」로 멈추고 알려 줍니다.

자동 처리는 Claude Code 가 열려 있는 동안만 돌고 7일 뒤 다시 띄워야 합니다. 이슈 하나만 맡길 때는 `/genia-works:work-on 이슈키` 를 씁니다.

> **주의**
>
> 자동 처리는 권한을 묻지 않는 모드라 이 AI 전용 터미널에서만 씁니다.

> **참고**
>
> Windows 처럼 플러그인 전환을 쓸 수 없으면 키를 직접 넘겨 띄웁니다. 셸 기록에 키가 남을 수 있습니다.
>
> ```
> GENIA_WORKS_TOKEN=<발급한 키> claude
> ```

### 맡는 프로젝트를 확인한다 {help=agent.repos label=코드 저장소}

에이전트 상세 **코드 저장소** 에는 이 AI 가 멤버이고 저장소가 연결된 프로젝트가 보입니다. 이 AI 는 이 프로젝트들만 맡습니다. 바꾸려면 프로젝트 설정의 멤버에서 이 AI 를 넣거나 뺍니다.

외부 AI 는 Works 가 코드를 받아 주지 않습니다. 도구를 띄운 컴퓨터에서 GitHub 에 로그인해 둡니다.

### 에이전트를 삭제한다 {help=agent.danger label=위험 구역}

에이전트 상세 맨 아래 **위험 구역** 의 **에이전트 삭제** 를 누르면 확인 창이 뜹니다. 삭제하면 실행을 멈추고 접속 키를 모두 폐기합니다. 지우는 방식은 에이전트가 남긴 기록에 따라 다릅니다.

- 코멘트·이력 같은 기록이 없으면 에이전트가 지워지고, 담당하던 이슈의 담당자에서도 빠집니다.
- 기록이 있으면 기록은 그대로 두고 이 워크스페이스에서 사용만 중지합니다(「남은 기록이 있어 삭제 대신 사용을 중지했습니다」). 담당하던 이슈의 담당자 칸에는 그대로 남으므로, 필요하면 이슈마다 담당자를 바꿉니다.

공통 비서로 지정된 에이전트를 지우면 지정도 함께 풀립니다. 개인 비서는 여기서 지울 수 없습니다.

## Claude Code 로 처음 실행한다

Claude Code 로 돌리면 사람이 컴퓨터를 켜 두고 AI 를 띄울 필요가 없습니다. 다음 순서로 설정하면 AI 가 일을 시작합니다.

1. **실행 환경** 탭에 실행 환경이 하나 있어야 합니다. 없으면 만듭니다([실행 환경을 추가한다](#agents.locations.create)).
2. **계정** 탭에 Claude 구독 계정을 넣습니다([계정을 추가한다](#agents.accounts.add)).
3. 에이전트 상세 **실행** 에서 실행 방식을 **Claude Code** 로 바꿉니다([실행 방식을 고른다](#agent.run.mode)).
4. **AI 계정** 의 **계정 고르기** 로 2에서 넣은 계정을 고릅니다([Claude Code 의 계정을 고른다](#agent.run.account.pick)).
5. **코드 저장소** 에서 맡는 프로젝트를 확인합니다([맡는 프로젝트를 확인한다](#agent.repos)).
6. **저장소 연결** 에서 맡는 프로젝트 저장소의 호스트마다 토큰을 연결합니다([저장소를 연결한다](#agent.run.repo)).
7. **상태** 의 확인 항목이 모두 **통과** 인지 보고 **시작** 을 누릅니다([실행을 시작하고 멈춘다](#agent.status.run)).
