# 캘린더 태그 구독 주소(iCal) 연동 안내

Gen:iA Works 캘린더에서 사용자가 일정에 붙인 **태그**별로, 그 태그가 붙은 일정을 iCalendar(.ics)로 내보내는 비밀 주소가 있다(WP-715).
사내 시스템이 이 주소를 주 단위로 불러 일정을 가져가는 용도다. 이 문서는 받는 쪽(사내 시스템) 개발자를 위한 것이다.

## 주소

사용자가 캘린더 사이드바의 태그 ⋮ 메뉴 → 「구독 주소…」에서 만들고 복사해 전달한다.

```
https://<워크스페이스 주소>/api/v1/public/calendar/feeds/<토큰>.ics
```

- **로그인이 필요 없다.** 토큰이 곧 권한이다(32바이트 난수, 43자). 주소를 아는 사람은 누구나 볼 수 있으니 서버 설정·비밀 저장소에만 둔다.
- 사용자가 「새 주소로 바꾸기」를 하면 **이전 주소는 바로 404**가 된다. 「주소 없애기」, 태그 삭제, 사용자가 워크스페이스에서 빠진 경우도 404 다.
  404 를 받으면 사용자에게 새 주소를 받아 다시 설정해야 한다.
- 응답은 캐시하지 말 것(`Cache-Control: no-store`). 태그를 붙이고 뗀 결과가 다음 요청에 바로 반영된다.

## 주 고르기 — `week`

```
…/<토큰>.ics?week=2026-W43
```

| 값 | 뜻 |
|---|---|
| `YYYY-Www` | ISO 8601 주. 주는 **한국 시간(Asia/Seoul) 월요일 00:00 ~ 다음 월요일 00:00** |
| 생략 | 요청 시점(한국 시간)이 든 이번 주 |
| 형식 오류·그 해에 없는 주(예: `2025-W53`) | `400` (본문은 짧은 평문 사유) |

- 그 주와 **겹치는** 일정이 모두 나간다(주 경계에 걸친 일정은 양쪽 주에 다 나온다).
- 반복 일정은 그 주에 드는 **회차마다 VEVENT 하나**로 펼쳐서 나간다(RRULE 은 보내지 않는다). 취소한 회차는 빠지고, 한 회차만 고친 경우 고친 내용으로 나간다.

## 응답

- `200 text/calendar; charset=utf-8`, 줄 끝 CRLF, 75옥텟 줄 접기(RFC 5545).
- `VCALENDAR` 머리: `VERSION:2.0`, `PRODID:-//Genia Works//Calendar Tag Feed//KO`, `CALSCALE:GREGORIAN`, `X-WR-CALNAME:<태그 이름>`.
- 그 주에 일정이 없으면 VEVENT 없는 빈 VCALENDAR 가 온다.

### VEVENT 항목

| 항목 | 내용 |
|---|---|
| `UID` | 일정 식별자 — 아래 「UID 규칙」 |
| `DTSTAMP` | 일정이 마지막으로 바뀐 시각(UTC) |
| `DTSTART` / `DTEND` | 시각 일정은 UTC(`20261021T010000Z`). 종일 일정은 `VALUE=DATE`(`DTEND` 는 다음 날 — 배타적 끝) |
| `SUMMARY` | 제목 |
| `LOCATION` | 장소(없으면 줄 없음) |
| `ORGANIZER` | 주최자 `mailto:` (+ `CN` 이름) |
| `ATTENDEE` | 참석자 `mailto:` (+ `CN` 이름, `PARTSTAT` = `ACCEPTED`·`DECLINED`·`TENTATIVE`·`NEEDS-ACTION`) |

- **설명(DESCRIPTION)은 보내지 않는다.** 회의 참가 링크·암호·내부 메모가 섞여 있어서다.
- **사람은 이메일로 가린다.** 이메일을 모르는 사람(주소 없는 참석자)과 AI 에이전트는 빠진다. 사내 사람·외부 사람 구분은 받는 쪽이 이메일 도메인으로 한다.
- 텍스트 값의 `\` `;` `,` 줄바꿈은 RFC 5545 대로 이스케이프돼 있다.

### UID 규칙 — 같은 UID = 같은 일정

| 일정 | UID |
|---|---|
| Microsoft 365(Outlook·Teams) 일정 | Outlook 의 `iCalUId` 그대로. 반복 회의는 회차마다 다른 값이 온다 |
| 앱에서 만든 단일 일정 | `wp-event-<id>@genia-works` |
| 앱에서 만든 반복 일정의 회차 | `wp-event-<시리즈 id>-<원래 회차 시작 UTC yyyyMMdd'T'HHmmss'Z'>@genia-works` |

- 한 회차만 시간을 옮겨도 그 회차의 UID 는 **원래 회차 시작 시각** 기준이라 바뀌지 않는다 → 받는 쪽은 UID 로 같은 일정을 갱신하면 된다.
- 사용자가 반복 일정을 「이후 모든 일정」으로 나눠 고치면 그 뒤 회차는 새 시리즈 id 로 UID 가 바뀐다.
- **이전에 받은 UID 가 이번 응답에 없을 때**(태그를 뗌, 일정 삭제·취소, 회차 이동으로 주 밖으로 나감 등) 어떻게 처리할지는 받는 쪽이 정한다.
  이 주소는 「지금 그 주에 태그가 붙어 있는 일정」만 알려 주고 삭제 이벤트를 따로 보내지 않는다. 주 단위 전체 교체(그 주 것을 지우고 다시 넣기)를 권한다.

## 알아 둘 제한

- **Microsoft 365 일정은 동기화 범위 안의 것만 나간다** — 지금 기준 **지난 1개월 ~ 앞으로 3개월**. 그보다 먼 주를 부르면 Outlook 일정은 비어 있을 수 있다
  (앱에서 만든 일정은 범위 제한 없음).
- M365 일정의 태그는 Outlook **범주(category)** 에서 온다. 동기화는 약 10분 간격이라 Outlook 에서 범주를 바꾼 뒤 반영까지 시간이 걸린다.
- 같은 회의를 사용자 본인 Outlook 사본과 다른 사람 초대 사본으로 둘 다 볼 수 있으면 본인 사본 하나만 나간다.
