# 데스크톱 이슈 작성 중 폐기 확인

## 의도와 목표

제목이나 본문을 입력한 데스크톱 이슈 작성 창을 닫다가 긴 초안을 잃는 일을 막는다. 모바일 시트의 기존 「작성 중인 내용을 버릴까요?」 확인창과 같은 문구와 선택지를 쓴다.

## 범위와 제약

- Esc, 바깥 클릭, 닫기(X), 취소는 입력이 있을 때 폐기 확인을 연다.
- 「계속 작성」은 제목과 본문을 보존하고 창을 연 채 둔다. 「버리기」는 창을 닫으며 다음에 열 때 입력을 비운다.
- 제목과 본문이 모두 비어 있거나 공백뿐이면 바로 닫는다.
- 이슈 생성 성공은 기존처럼 바로 닫는다.
- 모바일 동작과 이슈 생성 폼 훅은 바꾸지 않는다.

## 고려한 접근

1. 데스크톱 닫기 요청을 `f.hasContent` 로 가로채고 모바일과 같은 `AlertDialog` 를 둔다. 기존 판정과 디자인을 재사용하고 바뀌는 코드가 작아 이 방식을 선택한다.
2. 모바일·데스크톱 공용 확인 컴포넌트로 추출한다. 문구 중복은 없지만 이번 결함에 필요하지 않은 모바일 코드 변경도 생긴다.
3. 새 공용 미저장 폼 훅을 만든다. 다른 화면까지 바꾸는 추상화가 되어 이 범위에 비해 크다.

## 남은 구현 결정

Radix의 `onOpenChange(false)` 와 취소 단추를 공통 닫기 요청 함수로 보내고, 저장 성공 콜백은 기존 부모 콜백을 그대로 사용한다. 회귀 검증은 폼 테스트와 실제 브라우저 E2E 로 한다.

## 승인

WP-1443 본문이 기대 동작과 대상 닫기 경로를 명시하고 모바일에 동일한 기준 구현이 있다. work-loop의 설계 승인 자체 판단 규칙에 따라 이 설계를 승인한다.
