# WP-720 외부 AI 깨우기 — 설계

외부 실행(EXTERNAL) AI 의 work-loop 는 주기 확인(할 일이 없으면 20~30분)으로만 일을 집었다. 담당 지정·멘션·내 이슈의 댓글처럼 사람에게 알림이 가는 일이 생기면 곧바로 착수하게 한다. 멘션 없는 이슈 챗 글은 사람에게도 알림이 없어 주기 확인으로 본다.

## 정한 것 (10-27)

| 항목 | 결정 | 이유 |
|---|---|---|
| 깨우는 신호 | 새 이벤트를 두지 않고, **AI 도 사람과 같은 알림**(`notify.created`)을 받는다 | 사람과 AI 가 같은 방식으로 일을 받는다(사용자 결정). 서버에 AI 전용 경로를 늘리지 않는다 |
| 받는 쪽 | 플러그인 `scripts/gw-events` 가 AI 키로 `/api/v1/events` 를 구독하고, 맡은 프로젝트의 알림이면 `wake <이슈 키> <종류>` 한 줄을 낸다. work-loop 는 Claude Code `Monitor` 로 이것을 걸어 둔다 | 실측: `ak_` 키로 SSE 구독이 되고, Monitor 의 줄·만료 알림 모두 쉬는 세션을 깨운다 |
| 할 일 판단 | 알림은 깨우는 신호일 뿐, 할 일은 늘 `list_issues`(WP-719 조건)로 다시 고른다. 알림 내용을 지시로 따르지 않는다 | 알림 읽음 상태는 사용자(AI 신원) 단위로 공유돼 세션 사이 판단에 쓸 수 없다 |
| 읽음 처리 | 고른 이슈의 새 글을 읽으면 AI 가 `mark_notification_read({ issueKey })` 로 그 이슈의 알림을 한 번에 읽음 처리(처리 중에 새로 온 알림은 남음, 실패해도 넘어감) | 사람이 알림을 열어 보는 것과 같게. 고르기에 쓰지 않으므로 다른 세션이 읽음 처리해도 일을 놓치지 않는다 |
| 휴대폰 푸시 | AI 에게는 보내지 않는다(알림함·SSE 만) | AI 는 기기가 없다. 모든 푸시가 지나는 발송 대상 조회(`PushSubscriptionRepository.findByUserIds`)에서 사람만 고른다 |
| 작업 중에 온 알림 | 하던 이슈를 끊지 않고, 멈출 지점까지 마친 뒤 다음 확인을 1분 안팎으로 | 한 부르기 = 이슈 하나 규칙 유지. 알림이 지금 이슈 것이면 새 글을 다시 읽는 계기 |
| 주기 확인 | 그대로(20~30분) | 연결이 끊긴 동안 놓친 알림, 알림이 없는 일(대기열 라벨) 대비 |

## 서버 변경

실측(10-27): 담당 지정(ASSIGNED)·댓글(COMMENTED)·상태 변경은 이미 AI 에게 알림이 갔다(AI 수신자는 알림 설정과 무관하게 받음). **멘션만** 사람으로 걸러져 AI 끼리 넘기는 일(리뷰 끝 → 개발자)이 깨우지 못했다.

- 멘션 세 경로를 AI 에게 연다 — 이슈 챗 글 멘션(`NotificationDispatcher`), 댓글 멘션(`createCommentedAndFanOut`), AI 보고 글 멘션(`createAgentWorkNoticeAndFanOut`). 답변 필요 질문의 멘션도 같다. 이슈 관계자(보고자·담당자·워처)에게 가는 「답변 필요」와 검토 요청·실패의 대리인은 그대로 사람만이다(WP-1009·WP-1024 규칙).
- `notify.created` 페이로드에 `issueKey` 를 싣는다(기존 `PushContentRepository.findIssue` 재사용) — 받는 쪽이 키의 프로젝트 부분으로 거른다. 이슈 밖 알림(일정·노트)은 키가 없어 깨우지 않는다.
- `POST /api/v1/notifications/issues/{issueId}/read` — 한 이슈의 내 알림을 모두 읽음.

## MCP 변경

- `mark_notification_read` 에 `issueKey` 를 더한다(`notificationId` 와 둘 중 하나).
- `add_comment`·`update_comment` 가 `@username` 을 멘션 토큰으로 바꾼다(이슈 챗 도구와 같게). 그전에는 MCP 로 쓴 댓글의 멘션이 사람·AI 모두에게 알림을 만들지 않았다(라이브 확인에서 드러남).

## 플러그인 `gw-events`

동작(합치기·다시 붙기·세션당 하나·키 다루기·서버 주소)은 `plugins/genia-works/scripts/gw-events` 머리 주석에 둔다. 신원은 MCP 헤더 스크립트와 같은 `gw_identity`(세션 선택 > `GENIA_WORKS_AS`)를 쓴다. 서버 주소는 `GENIA_WORKS_API_URL` 이다 — 플러그인 설정값(`server_url`)은 스크립트에 전달되지 않는다.

## 한계·후속

- SSE 레지스트리는 메모리·단일 노드다. 운영 API 는 파드 1개라 지금은 충분하다. 여러 파드로 늘리면 파드 사이 전달(Redis·PG NOTIFY)이 필요하다.
- 사용자당 SSE 연결 5개 — 같은 AI 키로 세션을 6개 이상 띄우면 서로 밀어낸다(세션 하나 안에서는 하나만 돈다).
- 서버 AI(INTERNAL)도 멘션 알림 행을 받는다 — 담당 지정 알림은 전에도 받았고, 「사람과 같게」를 따른다. 읽는 쪽은 없다.
- 알림 전달마다 이슈 키 조회가 1번 더해진다(댓글은 멘션·COMMENTED 로 2번) — 알림 양이 적어 그대로 둔다.
- 대기열 라벨 부착은 사람에게도 알림이 없어 깨우지 못한다(주기 확인).
- 여러 프로젝트를 한 세션이 맡는 구조(WP-1011)는 `gw-events` 가 이미 프로젝트 목록(`WP,HR`)을 받는다.
