# 이슈 관계 유형 · 외부 링크 · 앱별 설정 (WP-887, WP-882 웨이브 3)

에픽 WP-882(Jira CLIM 이관) 웨이브 3. 이슈 사이 관계를 「차단」 하나에서 관련·중복·복제·원인과 관리자가 정의하는 유형으로 넓히고, Jira 처럼 다른 시스템에 남는 이슈를 외부 링크로 붙인다. 관계 유형 관리 화면을 두면서 설정 앱의 관리 메뉴를 「공통 관리 / 앱 설정」으로 나눈다.

## 왜

- 지금 이슈 사이 관계는 의존성(`blocks`/`blockedBy`)뿐이다. 「관련」을 의존성으로 넣으면 블로커 배지·차단 필터·타임라인 화살표가 틀어진다.
- CLIM 실데이터(이슈 317건, 2026-10-24 집계): 고유 링크 250건(이슈 양 끝으로 세면 360). CLIM 끼리 110건 — 관련 105·차단 2·원인 2·복제 1. 다른 Jira 프로젝트로 140건 — CL 112·TECH 23·INFRA 5(관련 131·원인 5·차단 3·중복 1). 별도로 CLIM 이슈 62건이 Jira `parent` 필드로 CL 에픽 12개에 속한다(CL-1867 v1.7.0 버그 픽스 16건 등). 웹 링크(remote link)는 표본 10건에 없었다.
- CL·TECH·INFRA 는 Jira 에 남는다 → 우리 쪽 이슈가 아니라 **외부 링크**로 옮긴다.

## 사용자가 정한 것

1. 관련·중복·복제·원인(+사용자 정의 유형) 관계는 **워크스페이스 안 다른 프로젝트 이슈에도** 걸 수 있다. 차단은 지금처럼 같은 프로젝트만.
2. **관리자가 관계 유형을 직접 정의**하는 기능을 이번에 넣는다. 범위는 **워크스페이스 전체 공통, 워크스페이스 관리자**가 관리한다(Jira·YouTrack·Plane 방식 — 프로젝트 사이 관계에 같은 유형이 쓰여야 해서).
3. 외부 링크는 관계 유형을 갖는다(시안: 「상위 에픽 · CL-1867 v1.7.0 버그 픽스 ↗」). 서버는 외부 URL 을 가져오지 않는다.
4. 설정 앱 관리 메뉴를 **앱별 설정**으로 나눈다 — 시안 A: 사이드바에 「앱 설정」 그룹, 그 아래 앱마다 항목 하나(「작업 관리」, 「노트」). 들어가면 그 앱의 설정 묶음. 노트 공유는 「노트」 아래로 옮긴다.
5. 사용 중인 사용자 정의 유형을 지울 때 「다른 유형으로 옮기기 / 관계도 함께 삭제」를 고른다(Jira 방식, 다른 서비스 조사 뒤 확정).

## 목표 / 하지 않을 것

목표
- 관계 유형별로 추가·삭제·표시되고, 블로커·차단 필터·타임라인 화살표에는 **차단만** 반영된다(지금과 같음).
- 외부 링크가 이슈 상세에 관계·키·제목으로 보이고, 누르면 원본이 새 탭에서 열린다.
- 워크스페이스 관리자가 관계 유형을 추가·편집·숨김·삭제한다.
- 관리자 전용 가져오기 경로로 CLIM 의 관계 250건·CL 에픽 소속 62건을 알림 없이 옮길 수 있다.
- AI·MCP 가 관계·외부 링크를 읽고 걸고 지울 수 있다.

하지 않을 것
- 관계로 이슈 목록 거르기(「CL-1867 에 속한 이슈」 필터), 중복이면 자동으로 닫기, 외부 링크 제목·미리보기 자동 가져오기(SSRF — WP-596).
- 차단의 저장 위치·블로커 계산 변경. 차단을 다른 프로젝트로 넓히기.
- 상위·하위(에픽→스토리→하위 작업)를 관계 목록에 섞기 — 지금처럼 「상위」 필드로 둔다.
- 프로젝트별 관계 유형.

## 관계 유형

### 표시 규칙 — 「이 이슈는 ___」

관계는 두 이슈 사이에 한 줄로 저장되고, 방향이 있으면 A(앞)·B(뒤)가 있다. 유형마다 **A 쪽 말**과 **B 쪽 말**을 둔다. 둘 다 **「이 이슈는 ___」의 서술어**다 — 그 이슈 화면의 관계 묶음 제목이고, 관계 추가 창의 「이 이슈는…」 선택지다. 방향이 없는 유형은 말이 하나다.

(시안에서 원인·중복·복제는 「상대가 무엇인지」로 적어 차단과 규칙이 달랐고, 추가 창에서 방향이 뒤집힐 수 있었다. 이 규칙으로 통일한다.)

### 기본 유형(모든 워크스페이스, 코드 키로 식별)

| 코드 | 이름 | A 쪽 말 (A→B) | B 쪽 말 | 범위 | Jira 대응 |
|---|---|---|---|---|---|
| `BLOCKS` | 차단 | 차단 중 | 차단됨 | 같은 프로젝트만 · 블로커 반영 | Blocks (A blocks B) |
| `RELATES` | 관련 | 관련 | (같음) | 워크스페이스 | Relates |
| `DUPLICATES` | 중복 | 중복임 | 원본임 | 워크스페이스 | Duplicate (A duplicates B) |
| `CLONES` | 복제 | 복제본임 | 복제 원본임 | 워크스페이스 | Cloners (A clones B, A 가 복제본) |
| `CAUSES` | 원인 | 원인임 | 결과임 | 워크스페이스 | Problem/Incident (A causes B) |
| `PARENT_EPIC` | 상위 에픽 | 에픽에 속함 | — | **외부 링크 전용** | Jira `parent` 가 다른 프로젝트 에픽 |

- 「차단됨」 묶음 제목은 화면에서만 지금처럼 「차단됨 (선행 필요)」로 덧붙여 보인다.
- 기본 유형은 이름·말을 바꾸거나 지울 수 없다(AI·MCP·가져오기가 코드로 부른다). `BLOCKS` 외에는 **숨기기** 가능 — 숨긴 유형은 새로 걸 수 없고 이미 걸린 관계는 그대로 보인다.
- `BLOCKS` 는 관계 유형 목록과 화면에는 다른 유형과 나란히 보이지만, **저장은 지금의 `issue_dependency` 그대로**다(아래 저장 구조). 블로커·차단 필터·타임라인·AI 블로커 배지 코드는 바꾸지 않는다.
- `PARENT_EPIC` 는 외부 링크에만 쓴다(우리 이슈끼리는 「상위」 필드).

### 사용자 정의 유형

- 워크스페이스 관리자가 만든다: 이름(1~30자, 워크스페이스 안에서 대소문자 무시 중복 불가 — 기본 유형 이름 포함), 방향(있음/없음), A 쪽 말·B 쪽 말(각 1~30자; 방향 없음이면 하나).
- 범위는 워크스페이스 공통, 다른 프로젝트 관계·외부 링크 모두에 쓸 수 있다.
- 편집: 이름·말은 언제든 바꾼다(이미 걸린 관계의 표시도 바뀐다). **방향 있음↔없음은 쓰이는 관계가 0건일 때만** 바꾼다.
- 숨기기 가능(기본 유형과 같은 뜻).
- 삭제: 쓰이는 관계(내부 관계+외부 링크)가 0건이면 확인만 묻고 지운다. 1건 이상이면 고른다:
  - **다른 유형으로 옮기기** — 대상은 숨기지 않은 유형 중 `BLOCKS`·외부 전용(`PARENT_EPIC`)을 뺀 것. 방향 있음→없음이면 방향이 사라지고(두 이슈 쌍 정규화) 같은 쌍이 이미 있으면 하나로 합친다. 방향 없음→있음이면 저장된 순서 그대로 A→B 가 된다. 외부 링크도 함께 옮긴다.
  - **관계도 함께 삭제** — 내부 관계·외부 링크 모두 지운다.
  - 옮기기·삭제와 유형 삭제는 한 트랜잭션이다. 이슈 이력은 남기지 않고 감사 로그에 한 줄 남긴다(건수 포함).
- 유형 수 상한: 워크스페이스당 사용자 정의 50개.

## 프로젝트 사이 관계와 가시성

- 걸기: 내 이슈의 **워크플로 편집 권한**(지금 의존성과 같음 — 프로젝트 멤버 또는 ADMIN, `assertMember`)과 상대 이슈 프로젝트의 **읽기 권한**(`canRead`)이 모두 있어야 한다.
- 지우기: 거는 것과 같은 규칙을 **주소의 이슈** 기준으로 본다 — 주소 이슈의 워크플로 편집 권한 + 상대 이슈 읽기. 그래서 어느 쪽 팀이든 **자기 이슈 화면에서** 지울 수 있다(상대 쪽 화면에서 지우는 길은 없다).
- 개인(PERSONAL) 프로젝트 이슈는 같은 프로젝트 안 관계만 — 다른 프로젝트와는 어느 쪽 끝도 될 수 없다.
- 상대 이슈를 **읽을 수 없는 사람에게는 그 관계가 아예 보이지 않는다**(GitLab 과 같음). 모든 노출 지점에 같은 검사를 건다:
  - 이슈 상세 관계 목록, 관계 개수 배지.
  - 이슈 이력(관계 추가·삭제 줄, 양쪽 이슈 모두) — 이력에는 상대의 프로젝트 키·번호·제목을 저장하되, 읽는 쪽이 상대 프로젝트를 읽을 수 없으면 그 이력 줄의 상대 정보를 「볼 수 없는 이슈」로 가린다(키·제목 모두).
  - 홈 활동 위젯, MCP `get_issue_detail`, AI 컨텍스트로 나가는 이슈 상세.
  - 실시간 갱신(SSE): 상대 이슈 쪽 알림은 상대 프로젝트 채널로만 보낸다.
- 읽기 검사는 행마다가 아니라 상대 프로젝트 id 를 모아 한 번에 한다.
- 이슈가 삭제(소프트 삭제)되면 그 이슈가 끝인 관계는 어디에도 보이지 않는다(행은 남긴다 — 지금 의존성과 같음).
- 표시 키: 같은 프로젝트면 `#12`, 다른 프로젝트면 `WPV-28`.

## 외부 링크

- 필드: 관계 유형(+방향 — 방향 있는 유형이면 이 이슈가 A 쪽인지 B 쪽인지), URL, 키(선택, 1~50자), 제목(1~300자).
- URL: `http`/`https` 만(서버에서 검사, 최대 2000자). 다른 스킴은 400. 서버는 그 주소로 요청하지 않는다.
- 화면: 새 탭(`target=_blank`, `rel="noopener noreferrer"`). 키는 URL 이 `…/browse/ABC-123` 꼴이면 화면에서 자동으로 채워 본다(편집 가능).
- 같은 이슈에 같은 URL 은 하나만(같은 유형·방향으로 다시 넣으면 그대로 둔다 — 가져오기 재시도 대비; 유형이 다르면 409).
- 이슈당 최대 50개.
- 외부 「차단」(`BLOCKS`)은 외부 링크 유형으로 고를 수 있고 「차단 중/차단됨」으로 보이지만, 블로커 계산·차단 필터에는 들어가지 않는다.
- 편집: 제목·키·유형을 고칠 수 있다(오타 정정). 이력에 남긴다.

## 저장 구조 (V213, 롤링 배포 호환 — 새 테이블만 추가)

- `issue_relation_type` — 워크스페이스 범위: `id`, `tenant_id`, `code`(기본 유형만, 워크스페이스 안 유일), `name`, `outward_label`, `inward_label`(방향 없음이면 NULL), `directed`, `external_only`, `hidden`, `sort_order`, `created_by`, `created_at`, `updated_at`. 이름 유일은 `(tenant_id, lower(name))`.
  - 기본 유형 행은 마이그레이션이 **모든 기존 워크스페이스**에 넣고, 새 워크스페이스는 `TenantProvisioningService` 가 넣는다. `BLOCKS` 도 행으로 둔다(목록·숨김 불가 표시용). 관계 행이 `BLOCKS` 를 가리키는 일은 없다(서비스·CHECK 로 막음).
- `issue_relation` — `id`, `tenant_id`, `type_id`, `source_issue_id`(A), `target_issue_id`(B), `created_by`, `created_at`. 유일 `(type_id, source, target)`. 방향 없는 유형은 저장 때 `source < target` 으로 정규화. `source <> target`. 이슈 FK 는 `ON DELETE CASCADE`.
- `issue_external_link` — `id`, `tenant_id`, `issue_id`, `type_id`, `issue_is_source`(방향 있는 유형에서 이 이슈가 A 쪽인가), `url`, `ext_key`, `title`, `created_by`, `created_at`, `updated_at`. 유일 `(issue_id, url)`.
- 세 테이블 모두 V89 의 테넌트 패턴(기본값 `current_setting('app.tenant_id')`, FK·인덱스, `ENABLE`+`FORCE ROW LEVEL SECURITY`, `USING`+`WITH CHECK` 정책).
- 새 권한 코드 `issue_relation_type:manage` — 모든 워크스페이스의 시스템 ADMIN 역할에 부여, `AdminPermissionCodes`·`TenantProvisioningService` 상수 갱신, `NewTenantProvisioningTest` 통과.
- 세 테이블을 `TenantPurgePlan` 에 넣는다.

## API

| 메서드·경로 | 누가 | 하는 일 |
|---|---|---|
| `GET /api/v1/issue-relation-types` | 로그인 사용자 | 유형 목록(숨김 여부·코드·말 포함, 정렬 순) |
| `GET /api/v1/admin/issue-relation-types` | `issue_relation_type:manage` | 위 + 유형별 사용 건수(내부·외부) |
| `POST /api/v1/admin/issue-relation-types` | 〃 | 사용자 정의 유형 추가 |
| `PUT /api/v1/admin/issue-relation-types/{id}` | 〃 | 이름·말·방향 편집(사용자 정의만) |
| `PUT /api/v1/admin/issue-relation-types/{id}/hidden` | 〃 | 숨김 켜고 끄기(`BLOCKS` 불가) |
| `DELETE /api/v1/admin/issue-relation-types/{id}?moveTo={id}` 또는 `?deleteLinks=true` | 〃 | 사용자 정의 유형 삭제(사용 중이면 둘 중 하나 필수, 없으면 409) |
| `GET /api/v1/issues/lookup?q=` | 로그인 사용자 | 관계 대상 찾기 — 호출자가 **읽을 수 있는** 모든 프로젝트(개인 제외, 현재 프로젝트는 포함)에서 키(`WPV-28`)·`#번호`·제목으로 최대 20건. 삭제된 이슈 제외 |
| `POST /api/v1/projects/{key}/issues/{n}/relations` | 워크플로 편집 | `{typeId, side: "source"|"target", target: {projectKey, number}}` — 이 이슈가 A(source)인지 B(target)인지. 방향 없는 유형은 side 무시. `BLOCKS` 면 400(의존성 API 를 쓴다). 같은 관계가 있으면 그대로 200(이력 없음). 응답은 갱신된 관계 목록 |
| `DELETE /api/v1/projects/{key}/issues/{n}/relations/{relationId}` | 위 「지우기」 규칙 | 멱등 204 |
| `POST /api/v1/projects/{key}/issues/{n}/external-links` | 워크플로 편집 | `{typeId, side, url, key?, title}` |
| `PUT /api/v1/projects/{key}/issues/{n}/external-links/{id}` | 〃 | 유형·방향·키·제목 편집(URL 은 바꾸지 않음 — 지우고 다시) |
| `DELETE /api/v1/projects/{key}/issues/{n}/external-links/{id}` | 〃 | 멱등 204 |

- 이슈 상세 응답(`IssueDetailResponse`)에 `relations[]`·`externalLinks[]` 를 더한다. 목록 API 에는 넣지 않는다.
  - `relations[]`: `id`, `typeId`, `typeCode`(기본 유형만), `label`(이 이슈 쪽 말), `issue: {projectKey, number, title, status, type}` — 읽을 수 있는 것만.
  - `externalLinks[]`: `id`, `typeId`, `typeCode`, `label`, `url`, `key`, `title`.
  - 차단은 지금처럼 `summary.blockedBy/blocks` 로 온다(변경 없음).
- 오류: 자기 자신 400, 없는/읽을 수 없는 대상 400(존재를 드러내지 않게 같은 메시지), 숨긴 유형 400, 다른 프로젝트에 `BLOCKS`·개인 프로젝트 400, 상한 초과 400.

## 이력 · 알림 · 실시간

- 관계 추가·삭제: **두 이슈 모두**에 이력 `RELATION_ADDED`/`RELATION_REMOVED`(Jira 와 같음 — 다른 프로젝트 팀도 자기 이슈에 누가 관계를 걸었는지 본다). 각 이슈 이력의 말은 그 이슈 쪽 말. 값: 유형 id·당시 말, 상대 `{projectKey, number, title}`. 차단(의존성) 이력은 지금 그대로(호출한 이슈에만).
- 외부 링크 추가·편집·삭제: `EXTERNAL_LINK_ADDED`/`EXTERNAL_LINK_UPDATED`/`EXTERNAL_LINK_REMOVED`, 값: 말·키·제목·URL.
- 웹 활동 타임라인·홈 활동 위젯에 새 이력 종류의 문구·아이콘을 더한다.
- 알림(인박스·푸시)은 내지 않는다 — 지금 의존성도 내지 않는다. AI 작업을 시작·재개하지 않는다(`updatedWithoutTouch`).
- 실시간: 두 이슈 각각 갱신 신호(다른 프로젝트면 그 프로젝트 쪽으로).

## 화면

시안(`.superpowers/brainstorm/…/relations-v3.html`, `settings-apps.html`)은 방향을 잡은 그림이다(원인·중복·복제 말은 위 표가 맞다). 순서: API·가져오기·MCP 를 먼저 만들고 → **실제 컴포넌트로 만든 시제품 캡처를 사용자에게 직접 보이고 승인받은 뒤** → 웹 화면을 만든다(기존 화면 변경 — 이슈 상세 레일, 설정 사이드바). main 머지는 웨이브 끝에 한 번.

### 이슈 상세 「관계」 그룹(지금 「의존성」 그룹 자리)

- 그룹 제목 「관계」, 개수 배지 = 차단 + 관계 + 외부 링크.
- 묶음은 **관계가 있는 말만** 보인다(지금처럼 빈 「차단됨/차단 중」에 「없음」을 늘 그리지 않는다). 순서: 차단됨 → 차단 중 → 나머지 유형의 정렬 순 → 「외부 링크」 묶음(줄마다 말 · 키 · 제목 · ↗).
- 전부 비면 「없음」 한 줄.
- 줄: 지금 `IssueLinkRow` 모양(유형 아이콘 · 키 · 제목 · 상태 · 제거). 다른 프로젝트 이슈는 키 `WPV-28`, 링크는 그 프로젝트 이슈 화면.
- 그룹 머리 「＋ 관계 추가」 하나로 창을 연다: 「이 이슈는…」(말 목록 — 숨긴 유형 제외) → 탭 「이슈」(찾기 — `lookup`; 차단을 고르면 같은 프로젝트만) / 「외부 링크」(URL·키·제목; 외부 전용 유형은 이 탭에서만).
- 차단 추가·삭제는 지금 의존성 API 를 그대로 쓴다. 차단 묶음의 기존 테스트 id(`blocked-by-list`, `blocks-list`, `issue-link-row-*`)는 유지한다.
- 모바일: 「＋ 속성」 시트 안의 같은 그룹(데스크톱과 같은 컴포넌트). 줄 제거는 지금처럼 터치는 ⋯ 메뉴.
- 편집 권한이 없으면(`viewerCanEditWorkflow` false) 추가·제거·편집 조작을 그리지 않는다.

### 설정 앱 — 앱별 설정(시안 A)

- 사이드바: 「개인 설정」 / 「워크스페이스 관리」(구성원·에이전트·역할·SSO·감사 로그) / **「앱 설정」**(작업 관리 · 노트). 「앱 설정」은 워크스페이스 관리자에게만.
- 「작업 관리」 `/settings/apps/work` — 지금은 「이슈 관계 유형」 한 묶음(설정이 둘 이상이 되면 탭). 표: 이름 · 이 이슈는(A 쪽 말) · 상대 쪽(B 쪽 말) · 구분(기본/추가) · 쓰는 곳(건수) · 동작(숨기기/편집·삭제). 추가·편집 창은 미리보기로 「#31 에서: … #12」, 「#12 에서: … #31」를 실제 말로 보여 준다. 삭제 창은 위 규칙.
- 「노트」 `/settings/apps/wiki` — 지금 노트 공유 화면을 그대로 옮긴다. 옛 주소 `/settings/wiki-sharing` 는 새 주소로 자동 이동.
- 페이지 제목(`documentTitle`), 설정 안내(`settingsGuides`), 모바일 설정 진입 목록도 같이 바꾼다.

## 가져오기(관리자 전용, 알림·이력 없음)

웨이브 2 의 가져오기 API 와 같은 권한(테넌트 ADMIN, AI 불가, 개인 프로젝트 불가)·같은 원칙(도메인 알림 이벤트를 내지 않음).

- **외부 링크**: `ImportIssueRequest.externalLinks[]` 추가(최대 50) — `{type, side, url, key, title}`. `type` 은 기본 유형 코드(`RELATES`, `PARENT_EPIC` …) 또는 사용자 정의 유형 이름. 이슈와 같은 트랜잭션에 넣고 이력은 남기지 않는다.
- **관계**: 이슈를 한 건씩 가져오므로 아직 없는 이슈와는 이을 수 없다 → 모든 이슈를 가져온 뒤 쓰는 일괄 호출 `POST /api/v1/projects/{key}/import/relations`:
  - 본문 `{relations: [{type, from: number, to: number | "KEY-n"}]}` 최대 1000건. `from` 은 이 프로젝트 번호, `to` 는 번호(같은 프로젝트) 또는 다른 프로젝트 키.
  - (구현 때 정함) 실제 본문은 `to` 를 두 필드로 나눴다 — `{relations: [{type, from, toNumber?, toKey?}]}`, `toNumber`(같은 프로젝트 번호)와 `toKey`(`"WPV-28"` 같은 이슈 키) 중 정확히 하나. 한 필드에 숫자·문자열을 섞으면 JSON 타입이 갈려 검증·문서가 번거로워서다.
  - 전부 검증한 뒤 쓰고, 하나라도 틀리면 아무것도 쓰지 않는다(400, 틀린 줄 번호 목록).
  - 멱등: 이미 있는 관계는 건너뛴다. `BLOCKS` 는 `issue_dependency` 로 가고 순환 검사를 거친다(순환이면 400).
  - 이력·알림 없음. 끝나면 프로젝트 단위 실시간 갱신 한 번.
- 사용법 문서 `docs/integrations/issue-import-api.md` 에 더한다: Jira 는 같은 링크를 양쪽 이슈에 보여 주므로(CLIM 360 → 고유 250) 링크 id 로 중복을 없애고 방향을 `type` 의 A→B 에 맞춰 보낼 것; Jira 링크 유형 → 코드 대응표(위 표); `parent` 가 다른 프로젝트 에픽이면 `PARENT_EPIC` 외부 링크로.

## AI · MCP

- `get_issue_detail` 출력에 `relations[]`(`{relationId, type, label, issueKey, title, status}` — 읽을 수 있는 것만)·`externalLinks[]`(`{externalLinkId, type, label, key, title, url}`)를 더한다 — 지우기 도구가 id 를 쓴다.
- 새 도구 `add_issue_relation` — `{issueKey, type(코드 또는 이름), side?, otherIssueKey? | externalLink?: {url, key?, title}}`; `remove_issue_relation` — `{issueKey, relationId | externalLinkId}`. 차단은 지금 `link_issues`(`linked` true/false — WP-812 가 옛 추가·제거 두 도구를 합쳤다) 그대로(`add_issue_relation` 에 `BLOCKS` 가 오면 그 도구를 쓰라는 오류).
- `get_project` 출력에 관계 유형 목록(숨김 제외, `{code?, name, outwardLabel, inwardLabel?, externalOnly}`).
- 도구 스냅샷·라벨·주석 테스트, AI 에이전트 이슈 서브에이전트 안내(`agent.md`) 갱신. 플러그인 버전 `0.1.11`(태그 `genia-works--v0.1.11` 은 웹 배포보다 먼저 또는 같이).

## 내가 정한 것 (사용자 확인 필요 표시)

- 차단은 저장·계산을 그대로 두고, 화면·유형 목록에서만 기본 유형으로 함께 보인다 — 합치면 블로커 계산·타임라인·검색·AI 배지가 모두 흔들리는데 얻는 게 없다.
- 관계 이력은 두 이슈 모두에 남긴다(Jira 와 같음, 차단은 지금 그대로 한쪽). 알림은 내지 않는다.
- 가져오기는 「이슈마다 외부 링크」 + 「모두 가져온 뒤 관계 일괄」 두 단계. 가져온 관계의 작성자는 가져온 관리자, 시각은 가져온 시각(Jira 링크엔 만든 사람·시각이 없다).
- 관계 지우기는 거는 것과 같은 규칙(주소 이슈 편집 + 상대 읽기) — 양쪽 팀 모두 자기 이슈 화면에서 지울 수 있다.
- 숨긴 유형: 화면·MCP 로는 새로 걸 수 없지만, 관리자 가져오기는 쓸 수 있다(이관 직전 숨김 때문에 일괄이 통째로 실패하지 않게).
- 관계 행이 `BLOCKS` 유형을 가리키지 못하게 하는 것은 서비스 검사(DB CHECK 는 다른 테이블을 못 본다).
- 개인 프로젝트는 다른 프로젝트와 관계를 맺지 못한다.
- 외부 링크 URL 은 http/https 만, 같은 이슈에 같은 URL 하나.
- 숫자 상한: 사용자 정의 유형 50, 이슈당 외부 링크 50, 관계 일괄 1000, 찾기 결과 20.

## 완료 조건과 검증

- API 통합 테스트: 유형 CRUD·숨김·삭제(옮기기 — 방향 있음→없음 정규화·중복 합치기, 외부 링크 동반 / 함께 삭제), 권한(일반 사용자 403, AI 는 일반 사용자와 같음), 기본 유형 편집·삭제 거부, `BLOCKS` 숨김 거부.
- 관계: 같은·다른 프로젝트 추가·삭제(양쪽 이슈 이력), 방향 없는 유형 정규화·멱등, 읽기 권한 없는 사람에게 상세·이력·개수에서 안 보임, 개인 프로젝트 거부, 숨긴 유형 거부, 삭제된 이슈 안 보임, 블로커·차단 필터 불변(관련만 건 이슈는 `blocked=false`).
- 외부 링크: 스킴 검사, 같은 URL 멱등/충돌, 상한, 편집 이력.
- 가져오기: 외부 링크 포함 가져오기, 관계 일괄(전부 아니면 무), `BLOCKS`→의존성·순환 400, 재시도 멱등, 알림 이벤트 0건.
- 새 워크스페이스에 기본 유형·권한이 들어간다(`NewTenantProvisioningTest`).
- MCP: 도구 스냅샷·단위 테스트.
- 웹 E2E: 관계 추가(같은·다른 프로젝트·외부 링크)·삭제·표시, 차단 기존 흐름 그대로, 설정 「앱 설정」 메뉴·관계 유형 관리(추가·편집·숨김·삭제 두 경로), 옛 노트 공유 주소 이동, 관리자 아닌 사람에게 안 보임, 모바일 시트.
- 전체 회귀(`pnpm test:full`) 통과.
