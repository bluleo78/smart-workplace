# LNB/GNB 레이아웃 재정리 — 설계

- 날짜: 2026-06-01
- 대상: `apps/workplace-web`
- 참고: `smart-fire-hub` (`apps/firehub-web`)의 `AppLayout` 패턴

## 1. 배경 / 문제

현재 workplace-web의 네비게이션이 두 군데로 흩어져 있고 일관성이 없다.

- **GNB(상단 헤더, `h-14`)**: 로고 + 프로젝트/내 태스크/관리자/AGENT 링크 + 테마 토글 + 유저 드롭다운 (`components/layout/AppLayout.tsx`)
- **LNB**: 홈 페이지(`/`)에만 존재하는 `ModuleSidebar`(모듈 홈/이슈 + 팀 본인/AI 동료). 다른 페이지는 LNB 없이 `container` 중앙 정렬.

fire-hub는 반대로 LNB 중심(좌측 사이드바가 주 네비, 별도 GNB 없음, collapse+localStorage, 모바일 오버레이)이다. 이를 참고하되 **그대로 미러링하지 않는다** — fire-hub의 LNB는 "기능 카탈로그"(데이터셋/쿼리/차트…)인데, workplace는 **AI Native**(홈의 AI 캔버스 + 챗이 일을 시작하는 주 경로)라 LNB의 정체성을 다시 정의해야 한다.

## 2. 핵심 결정 (브레인스토밍 결과)

### 2.1 네비 모델: LNB 중심, 상단 GNB 제거
fire-hub처럼 좌측 단일 네비로 통합. 별도 상단 GNB는 제거한다.

### 2.2 LNB = "앱 런처" (순수 최소화)
AI Native에서 일을 시작하는 주 경로는 **챗/캔버스**다. LNB가 기능 메뉴를 그대로 들고 있으면 진입점이 둘로 경쟁한다. 따라서 LNB는 "기능 카탈로그"가 아니라 **명시적으로 모듈(앱)을 띄우는 런처**로 역할을 한정한다 (OS dock / Slack 워크스페이스 레일에 가까움). 모듈 내부의 깊은 네비는 **모듈이 책임**진다.

LNB 구성:
```
로고 (Smart Workplace) + collapse 토글
─────────────
홈      (/)          ← AI 캔버스 + 챗 도크
이슈    (/projects)
─────────────
Chat · Wiki · Drive  (coming soon — 흐림/비활성, 클릭 불가)
─────────────  (하단 고정)
관리    (어드민만)    ← 클릭 시 관리 모듈 진입
유저 메뉴            ← 프로필 / 테마 토글 / 로그아웃
```

- 팀(본인/AI 동료)·최근 세션 같은 맥락은 LNB에 넣지 않는다. AI 챗과 각 모듈이 책임진다.
- collapse 시: 아이콘 레일(`w-[52px]`) + Tooltip / 펼침 시: `w-60`. 상태는 `localStorage`에 저장.
- 활성 표시: `location.pathname.startsWith(href)` (fire-hub 로직 재사용).
- 반응형: 데스크탑 `lg:static`, 모바일 `fixed` 오버레이 + 햄버거 토글.

### 2.3 2단 사이드바 = 모듈 소유 2차 네비
LNB(앱 레일)는 최소로 유지하고, **모듈에 진입했을 때만** 그 모듈 소유의 2차 사이드바가 나타난다. 이는 "LNB=순수 런처, 모듈 내부 깊은 네비는 모듈이 책임" 원칙과 정확히 부합한다(LNB가 아니라 모듈 컴포넌트).

레이아웃:
```
┌─────┬──────────────┬──────────────────────┐
│ 앱  │ 모듈 2차      │  콘텐츠               │
│레일 │ 사이드바      │                       │
│ LNB │ (모듈 소유)   │                       │
└─────┴──────────────┴──────────────────────┘
```

모듈별 2차 사이드바:
- **홈**: 2차 사이드바 **없음**. 콘텐츠 영역 = AI 캔버스(`HomeCanvas`).
- **이슈**: `[내 태스크]`(cross-project) + `[프로젝트 목록]`(프로젝트A·B·C… + 새 프로젝트). 어느 프로젝트 보드에 있든 즉시 다른 프로젝트/내 태스크로 전환 — Linear/Jira/GitHub Projects 표준. workplace v1 주력 도메인이 이슈라 투자가 정당화됨.
- **관리**(어드민): `사용자 / 역할 / 감사 로그 / AGENT`. 현재 GNB의 "AGENT"(비서 관리)는 독립 항목이 아니라 **관리 모듈 2차 사이드바로 흡수**.

향후 Chat/Wiki/Drive도 각자 필요하면 같은 패턴으로 자기 2차 사이드바를 가진다 → **일반화된 모듈 셸 패턴**.

#### v1 트레이드오프(기록)
이슈 내부 네비를 "랜딩 탭"이 아니라 2단 사이드바로 가는 이유: 내 태스크가 cross-project이고 프로젝트 전환이 잦아 **상주 네비**가 필요하기 때문. 랜딩 탭 방식은 프로젝트 보드에 깊이 들어가면 매번 랜딩을 거쳐야 해 부적합. (목적지가 2~3개로 적은 모듈이라면 탭으로 충분했겠지만 이슈는 프로젝트 수만큼 늘어남.)

### 2.4 챗 전역 상주 — 상단 AI 칩 런처 (구현 중 개정)
현재 챗(`FloatingChat`)은 `HomeShell` 안에 있어 **홈에서만** 뜬다. AI Native에서 "챗이 주 경로"이려면 이슈 보드 등 **모든 모듈에서 상주**해야 한다. 따라서 챗을 글로벌 셸로 끌어올린다.

> **개정(구현 중 결정):** 처음에는 #51의 "하단 도크"를 전역으로 올리려 했으나, 항상 보이는 **하단 중앙 입력바가 다른 페이지의 하단 UI를 가리고**(프로젝트 삭제·토큰 등록 버튼) **이슈 상세 페이지의 자체 하단 컴포저와 충돌**하는 회귀가 드러났다. 그래서 fire-hub의 **상단 중앙 AI 칩(런처)** 패턴을 채택한다. 하단을 점유하지 않아 충돌이 사라진다.

- **챗 진입 UI**: 전역 셸 콘텐츠 영역 상단 중앙에 작은 **AI 칩(런처)** 상주(`absolute top-2`, `pointer-events` 제어). 클릭/⌘K 로 아래에 패널(transcript + 입력)이 펼쳐짐. 평소엔 칩만 보이므로 페이지 UI를 가리지 않음.
- **캔버스(홈 산출물)**: 홈 모듈 전용. 캔버스는 홈에만 존재한다.
- **비-홈 모듈에서 챗 제출 시 거동**: 쿼리를 제출하면 **홈으로 라우팅한 뒤 캔버스에 결과를 구성**한다 — "챗 → AI compose → 캔버스" 주 경로를 보존. (`GlobalChatDock`의 `handleSubmit`가 담당.)
- 세션 상태(`useHomeSession`)는 `HomeSessionProvider`(AppLayout 레벨)로 끌어올려 칩 패널(전역)과 캔버스(홈)가 공유.

## 3. 컴포넌트 / 파일 변경 (구현 범위)

신규/변경(확정된 레이아웃 골격):

- **신규** `components/layout/AppRail.tsx` — 앱 런처 LNB. fire-hub `AppLayout.tsx`의 사이드바 부분(로고/collapse/localStorage/활성표시/모바일오버레이) 패턴 이식. 항목: 홈/이슈/coming-soon/(관리, 어드민)/유저메뉴.
- **변경** `components/layout/AppLayout.tsx` — 상단 GNB 헤더 제거. `flex h-screen` 셸로 전환: `AppRail` + (모듈 2차 사이드바 슬롯) + `<Outlet/>` + **글로벌 챗 도크**.
- **신규** 모듈 2차 사이드바 컴포넌트:
  - `components/issue/IssueSidebar.tsx` — 내 태스크 + 프로젝트 목록 + 새 프로젝트.
  - `components/admin/AdminSidebar.tsx` — 사용자/역할/감사로그/AGENT.
  - 2차 사이드바는 해당 모듈 라우트의 레이아웃에서만 렌더(중첩 라우트 레이아웃 또는 라우트별 셸).
- **변경** `components/home/HomeShell.tsx` — `ModuleSidebar` 제거(앱 레일이 대체). 홈은 2차 사이드바 없이 캔버스만. **`h-[calc(100vh-3.5rem)]`의 GNB 높이(3.5rem) 차감 제거** (GNB가 사라졌으므로).
- **이동/제거** `components/home/ModuleSidebar.tsx` — 앱 레일로 역할 흡수, 제거(또는 앱 레일로 대체).
- **이동** `components/home/FloatingChat`(챗 도크) — `HomeShell` → 글로벌 셸(`AppLayout`)로 끌어올림. `useHomeSession` 상태 범위/Provider 위치 조정 필요.
- **변경** 라우팅(`App.tsx`) — GNB 링크 제거에 맞춰 모듈/2차 사이드바 레이아웃 구조 반영. 기존 라우트 경로(`/projects`, `/me/watched`, `/admin/*`)는 유지.

스타일: 기존 Tailwind/shadcn 토큰 사용. fire-hub의 oklch 토큰을 그대로 가져오지 않고 workplace 기존 디자인 토큰을 따른다.

## 4. 비범위 (이번 작업 제외)

- 신규 모듈(Chat/Wiki/Drive)의 실제 구현 — LNB에 coming-soon 표시만.
- 이슈/관리 모듈 내부 페이지의 기능 변경 — 네비 진입 구조만 정리.
- 디자인 토큰/테마 색상 개편.
- 비-홈 모듈에서 챗 제출 시의 상세 동작 로직 — 권장 기본값(홈 라우팅 후 캔버스 구성)만 명시, 세부는 구현 시.
