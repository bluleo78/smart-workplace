# HTML 보이는 화면 편집 — 런타임 DOM 이 원본에 섞이지 않게 (WP-1309)

작성일: 2026-11-02 · 상위 설계: WP-1299 첨부 `wiki-html-editing-design.md` §3-2·§3-3·§6-3

## 배경 / 문제

HTML 문서 페이지의 「편집」과 노트 HTML 블록의 「글자 고치기」는 원본 화면을 **스크립트까지 실제로 돌린** 격리 iframe 위에서 글자를 고친다.
그런데 iframe 의 DOM 에는 원본에 없던 것이 섞여 있다.

- 스크립트가 만든 요소 — 차트 SVG, 계산 결과 카드, 탭 내용 등
- 스크립트가 바꾼 글자 — `#total.textContent = 합계` 같은 숫자
- 편집 도구가 넣은 것 — 점선 덮개, 서식 도구, `contenteditable`, 격리용 `<base>`·스타일·스크립트

이 DOM 을 통째로 직렬화해 저장하면 다음에 열 때 스크립트가 한 번 더 그려 차트가 두 벌이 되고, 스크립트가 채운 숫자가 원본에 굳는다.
웹 빌더 라이브러리(GrapesJS 류)는 쓰지 않는다(설계 §6-3) — 원본을 자기 형식으로 바꾸기 쉽고 무겁다.

## 결정 — 「원본 번호」로 되돌리기 (iframe DOM 은 저장에 쓰지 않는다)

| 단계 | 어디서 | 무엇을 |
|---|---|---|
| 1. 표시 | 부모 | 원본을 **스크립트 없이** 파싱(문서면 `DOMParser`, 조각이면 `<template>`)해 원본의 모든 요소에 문서 순서 번호 `data-wp-src="n"` 를 단다. 글자를 고칠 수 있는 요소에는 원본 글자 지문 `data-wp-t`(공백 정리 + FNV-1a)를 단다. 이 문서를 격리 iframe 에 띄운다 |
| 2. 편집 | iframe | 지문이 달린 요소 중 ① 번호가 문서에 하나뿐 ② 자손이 모두 번호를 가짐(런타임 자식 없음) ③ 지금 글자 지문이 원본과 같음(스크립트가 글자를 안 바꿈) — 셋을 모두 만족하는 것만 점선·편집을 켠다. 고친 요소의 **번호와 innerHTML** 만 부모에 보낸다 |
| 3. 되돌리기 | 부모 | 1 에서 파싱해 둔 **깨끗한 원본**(번호를 달지 않은 것)의 사본(`cloneNode`)에서 같은 번호의 요소를 찾고, 받은 innerHTML 을 정리기로 거른 뒤 **그 요소의 자식만** 바꿔 직렬화한다 |

### 비용 — 한 번 파싱, 바뀐 것만 보내기

- 준비(`prepareHtmlTextEdit`)는 화면을 띄울 때 한 번 원본을 파싱해 깨끗한 원본과 고칠 수 있는 번호 집합을 쥐고, 번호·지문은 사본에 달아 띄울 문서를 만든다. 되돌리기(`apply`)는 입력이 쉴 때마다 불리지만 다시 파싱하지 않고 깨끗한 원본을 복제해 쓴다
- 바로 전과 같은 고친 것(같은 항목 객체들 — 새로 받은 것 없는 flush)이면 앞 결과를 그대로 돌려준다 — 「저장」·「소스」 전환이 다시 직렬화하지 않는다
- iframe 은 지난번 보낸 뒤 바뀐 요소만 보낸다(flush 에는 빈 목록으로라도 답한다). 부모가 ref 별로 합친다(처음 받은 순서 — 새 문단이 앞 문단 뒤에 온다)
- iframe 의 「고칠 수 있나」 판정(문서를 훑는다)은 요소별로 기억하고, 문서가 바뀌면(`MutationObserver` — 문서 스크립트의 요소·글자·번호 속성 변화, 표시 덮개·서식 도구 안 변화는 뺀다) 잊는다

번호는 속성이라 요소와 함께 움직인다 — 스크립트가 원본 요소를 옮겨도 번호가 따라가고, 새로 만든 요소에는 번호가 없다.
iframe DOM 을 직렬화하지 않으므로 런타임 DOM·편집 표지·주입 스크립트가 원본에 들어갈 길이 구조적으로 없다.

### 고칠 수 있는 요소

- 태그: `p·h1~h6·li·td·th·dt·dd·blockquote·figcaption·caption·label·div·summary` 와 인라인 글(`span·a·b·strong·i·em·…`)
- 자손이 모두 인라인 글·`br`·`img` 뿐이고 글자가 있다. `svg·canvas·script·style·button·select·textarea·template·noscript·iframe·head` 안은 뺀다
- 그중 **가장 바깥 것** 하나가 고칠 단위 — 문단 안 `<b>` 를 따로가 아니라 문단 하나로 고친다
- 되돌리기도 같은 판정을 다시 한다 — 이 집합에 없는 번호(스크립트·스타일·카드 묶음)로 온 고침은 버린다

### 정리기 (부모만 한다)

- 원본 서식 요소(같은 요소 아래, 같은 태그, 처음 나온 번호) → **원본 속성째 되살린다**(`<a class href>`·`<span style>` 를 잃지 않게)
- 새 요소 → `b·strong·i·em·u·s·code·sub·sup·small·mark` 는 속성 없이, `a` 는 `http(s)`·`mailto` href 만, `span` 은 글자색(`style="color"`)만
- 웹에서 붙인 모양: `font-weight ≥ 600` → `<b>`, `font-style: italic` → `<i>`, 글자색·`<font color>` → `<span style="color">`. Google Docs 의 `<b style="font-weight:normal">` 은 굵게로 치지 않는다
- 블록(`p·div·li·제목…`)은 풀고 사이에 `<br>`, `script·style·iframe·svg·폼` 은 내용까지 버린다, 주석은 버린다
- 붙여넣기도 iframe 이 기본 동작을 막고 클립보드를 부모에 보내 → 부모가 정리 → iframe 이 커서 자리에 넣는다(보이는 것 = 저장되는 것)

### 새 문단

「문단 추가」·Enter 는 iframe 에서 새 요소(`data-wp-new`)를 만들고 `{ref: n:<id>, after: 앞 요소 ref, cls}` 로 보낸다.
부모는 원본(문단을 둘 수 있는 태그만)이나 앞 새 문단 바로 뒤에 `<p>`(목록 항목이면 `<li>`)를 넣는다. 빈 새 문단은 넣지 않는다. Enter 는 커서 뒤 글자를 새 문단으로 나눈다.

### 직렬화

- 고친 것이 없거나 정리 결과가 원본 innerHTML 과 같으면 **원본 글자를 그대로** 돌려준다
- 고쳤으면: 문서는 `머리말(원본 글자 그대로 — DOCTYPE·앞 주석) + documentElement.outerHTML`, 조각은 `template.innerHTML`(앞의 `<style>·<script>` 가 `<head>` 로 옮겨지지 않는다)

**한계(받아들임)**: 고친 것이 있으면 문서 전체를 DOM 직렬화로 다시 쓴다 — 속성 따옴표, 빠진 닫는 태그, `<tbody>` 같은 파서 보정이 글자로 드러난다. 보이는 모양·스크립트 동작은 같다.
원본 글자 위치(오프셋)를 지키는 부분 바꾸기는 HTML 토크나이저를 따로 두어야 해 이번 범위 밖으로 둔다.

## 보안

- iframe 은 지금처럼 `SandboxedHtmlFrame`(allow-scripts, **allow-same-origin 없음**) — 편집 스크립트도 그 안에서만 돈다. 노트 스크립트가 멈춰 있으면 우리 스크립트만 돈다(아래 「WP-1290 와의 관계」)
- 메시지는 보낸 창(`event.source`)과 iframe 마다 일회 토큰으로 가린다(고르기 `wp-html-picker` 와 같은 꼴, 종류는 `wp-html-edit`). 봉투 확인·보내기·iframe 스크립트 머리(TOKEN·post·부모 명령 가리기)는 `lib/frameMessages`, 부모 쪽 통로는 `useFrameChannel` 하나를 둘이 함께 쓴다(스크립트는 따로)
- 같은 iframe 의 문서 스크립트는 토큰을 읽어 흉내 낼 수 있다 → 부모는 받은 고침을 **다시 판정**(고칠 수 있는 번호인지)하고 **다시 정리**한다. 원본 스크립트·스타일을 바꿀 수 없다
- AI 요청에 실리는 고른 요소의 outerHTML 에서는 편집 표지(`data-wp-*`·`contenteditable`)를 걷는다 — 고르기 스크립트가 iframe 안에서 요소 사본의 표지를 걷은 **뒤** 300자로 자른다(자른 뒤 걷으면 끊긴 표지 꼬리가 남는다)

## 화면

- HTML 문서 「편집」 = 보이는 화면 편집(기본). 편집 중 「소스」 = 소스 + 미리보기(같은 편집 세션 소스), 「편집」으로 돌아오면 고친 소스로 다시 띄운다. 저장·취소·잠금은 WP-1308 흐름 그대로 — 「저장」은 iframe 에 남은 입력(쉬기 전 300ms)을 flush 로 받은 뒤 보낸다
- 막대 아래: ◎ 고르기 · ✦ AI로 고치기(HTML 블록과 같은 입력 칸 — 「적용」하면 편집 소스를 통째로 바꾸고 화면을 다시 띄운다, 저장은 「저장」)
- 떠 있는 서식 도구(iframe 안, 어두운 막대): 굵게 · 기울임 · 링크(주소 칸 — sandbox 가 prompt 를 막는다) · 색(견본 7개) · + 문단
  - 자리: 요소 위(8px 띄움) → 글자 오른쪽(같은 줄) → 요소 아래 순으로 보고, 창 안에 들고 고치는 글자와 겹치지 않으면서 남의 글자를 가리지 않는 첫 자리에 둔다(없으면 가장 덜 가리는 자리, 창보다 큰 요소면 창 안에 붙임). 가리는지는 iframe 이 후보 안 몇 점의 `elementFromPoint` 로 맨 위 요소를 찾아 그 글자 줄 상자와 겹친 넓이로 잰다 — 카드 값 바로 위 이름표처럼 「위 줄」을 가리지 않게. 고른 자리는 기억해 입력마다 뛰지 않고, 창을 벗어나거나 늘어난 글자에 닿을 때만 다시 고른다(`wpBarPos`·`wpBarFits`, `HTML_TEXT_EDIT_CORE`)
  - 보이는 대로 저장: 이미 굵은 제목에서 「굵게」, 기울임 스타일 안에서 「기울임」을 누르면 브라우저가 `<span style="font-weight: normal">`·`font-style: normal` 로 끈다. 정리기는 **고친 것(편집 경로)에서만** 이 끄기 값(굵기 `normal`·`400`, 기울임 `normal` — 그 밖의 값·CSS 는 버림)을 span 으로 남긴다. 붙여넣기 정리에서는 버린다 — 웹에서 복사한 HTML 은 span 마다 `font-weight: 400`·`font-style: normal` 을 달아, 남기면 붙인 곳(제목 등)의 모양을 깬다(붙인 결과는 정리한 뒤 iframe 에 넣으므로 그때도 보이는 대로다). 굵게는 `b`/`strong`·`span style=font-weight:bold|≥600`(→ `<b>`), 색은 `span style=color`·`<font color>`(→ `<span style="color">`) 로 같은 꼴이 된다. 브라우저가 원본 span 의 style 을 고쳤으면 원본 속성은 그대로 되살리고 안쪽에 달라진 서식(굵기·기울임·색)만 더한다
- 두 화면의 iframe 배선(준비 → 고르기·글자 고치기 스크립트 → 창 붙이기 → 고르기 중 멈춤)은 `useHtmlEditFrame` 하나다. 막대·칩·AI 칸 모양은 범위 클래스 `.wiki-html-embed-scope`(블록 NodeView 뿌리·문서 편집 막대)에 건다
- HTML 블록 막대에 「글자 고치기」: 켜면 그때 소스로 편집 화면을 띄우고, 입력이 쉴 때마다 고친 것을 **한 거래**로 노드 글자에 넣는다(동료에게 바로 간다). 넣기 전 소스가 내가 마지막으로 쓴 것과 다르면(동료 편집) 덮지 않고 끝낸다(알림). 켜 있는 동안 「소스 편집」은 막고, 「AI로 고치기」를 열면 먼저 끝낸다

## WP-1290 와의 관계 — 노트 스크립트가 멈춘 동안의 편집

WP-1290 은 노트(·HTML 문서)의 스크립트를 기본 멈춤으로 두고 스위치로 켠다. 멈춤은 iframe sandbox 에서 `allow-scripts` 를 빼는 것이라 그대로는 우리
편집 스크립트(글자 고치기·고르기·높이 보고)도 돌지 않는다. 그래서 편집 화면만 **「우리 스크립트만」** 으로 띄운다.

| 상태 | iframe | 문서 스크립트 | 우리 스크립트 |
|---|---|---|---|
| 스크립트 켜짐 | `allow-scripts`, 지금과 같음 | 돈다 | 돈다 |
| 멈춤 + 편집(HTML 문서 「편집」·블록 「글자 고치기」) | `allow-scripts` + 맨 앞 CSP `script-src 'nonce-…'; object-src 'none'; frame-src 'none'` | 막힘 | nonce 를 달아 돈다 |
| 멈춤 + 편집 아님 | `allow-scripts` 없음(WP-1290 그대로) | 막힘 | 돌지 않음 — 블록 고르기는 막고 까닭을 보인다 |

- 막기는 두 겹이다. ① CSP(`SandboxedHtmlFrame pageScripts=false` → `buildSandboxDoc` nonce) — nonce 없는 `<script>`·인라인 이벤트·`javascript:` 주소를 막는다. nonce 는 문서를
  만들 때마다 새로 뽑고 우리 문자열(`ownScript`·문서 안 이동 처리기)에만 단다. ② 띄울 사본 DOM 정리(`prepareHtmlTextEdit` `inertPage`) — CSP 가 못 막는
  `<meta http-equiv=refresh>`(allow-scripts 면 자동 이동이 풀려 CSP 없는 data: 문서로 갈 수 있다)와 링크 `target`(iframe 자체를 data: 로 옮김)을 걷고,
  `<script>`·`<noscript>`·`on*` 도 걷는다. noscript 는 스크립트 꺼짐으로 파싱한 사본을 스크립트 켜짐 iframe 이 다르게 읽어 스크립트가 되살아나는 길이다.
  번호를 단 **뒤** 사본에서만 걷어 번호·되돌리기(깨끗한 원본)는 그대로다 — 저장에는 원본 스크립트가 남는다.
- 런타임 DOM 보호는 두 경우 모두 그대로다. 켜짐이면 지금처럼 번호·지문으로 가리고, 멈춤이면 문서 스크립트가 돌지 않아 런타임 DOM 이 생기지 않는다.
- **실행 여부는 편집 화면을 띄울 때 굳힌다.** 고친 글자가 들어가면 블록 지문이 바뀌어 노트 스크립트가 멈추는데(WP-1290), 그때마다 iframe 을 다시 띄우면 커서·입력이 끊긴다.
  고친 글자는 정리기를 거쳐 스크립트를 더하지 못하므로 그 편집 동안은 띄울 때의 상태로 둔다.
  - 블록 「글자 고치기」: 켤 때의 노트 스위치로 끝날 때까지 간다. 「스크립트 멈춤」 표지도 그 값을 따른다. 끝내면 WP-1290 규칙대로(내용이 바뀌었으면 멈춤).
    노트에 알리는 소스는 화면에 보이는 것(끈 직후엔 고친 소스)이다 — 늦춘 미리보기를 알리면 그것이 따라올 때 지문이 한 번 더 바뀌어 그 사이 켠 스위치가 다시 꺼진다.
  - HTML 문서 「편집」: 노트에 알리는 소스는 편집을 연 때·소스에서 돌아온 때·AI 적용 때의 소스다(`EditScreen.scripts`) — 화면에서 고친 글자로는 바뀌지 않는다.
    띄울 때 값은 허용한 묶음과 바로 견준다(`useNoteAllowsSource` — 알리기가 닿기 전 첫 렌더의 지난 값으로 허용 안 된 이어 고치기 원본의 스크립트가 한 번 돌지 않게).
    편집 중 스위치를 바꾸면 남은 입력을 받아(flush) 지금 소스로 다시 띄운다(`onRebase`) — 같은 iframe 의 sandbox 는 바꿀 수 없다.
- 블록 고르기는 글자 고치기 중이면 멈춤이어도 쓸 수 있다(같은 「우리 스크립트만」 iframe). 글자 고치기 밖에서 멈춘 블록은 WP-1290 그대로 고르기를 막는다.
